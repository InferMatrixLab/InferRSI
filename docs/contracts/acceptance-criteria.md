# T01–T40 unique outcomes (specified results, not executed tests)

Status: **Proposed**. T01–T35 keep the original baseline wording and unique outcomes; T36–T40 are added by D023. Every row is a **specification**. Apart from the documentary construction evidence called out in section 5, **no row has been executed as a passing runtime test**. Schema validation is not acceptance of this table.

D003's non-terminal policy has already been chosen by the author, and C3 follows the exact gate path in D018/D020. P1 is a fixture protocol only: an independent F format error may FAIL; a trustworthy C correctness error may FAIL; M requires complete measurement and cleanup evidence. No other valid evidence implies a substitute. One scope does not override another.

## 4. Negative assertions not implied by T36–T40

T36–T40 must not be read as establishing any of the following:

- Any internal location change leaves `prepared_id` unchanged.
- A code digest may be implemented only through one DTO field; equivalent projections are forbidden.
- The first-wave `prohibited_first_wave` list is a permanent ban, or a shell→Apps edge is permanently allowed without its own review.
- Disconnect replay is interpreted as forbidding reuse of the original attempt.
- Locating or extracting bytes in `collect_candidate` is upgraded to a proven Apps scoring overreach.
