## 完成后新增什么能力

仓库已经有 Workbench、SkillEval、Agent 日志与部分用量记录。本次补齐的是这些能力在真实工程优化任务上的接入。

| 当前缺口 | 完成后的目标能力 |
| --- | --- |
| NPU 工具试点运行的是预写参考候选 | 接收真实 Agent 产生的代码，独立检查与测量 |
| 外部目标已有通用命令入口，但产物和评测记录需手工拼接 | 有明确测试和 benchmark 的外部项目任务也能进入同一条链路 |
| Agent 消耗与 NPU 代码性能尚未完整关联 | 每次任务记录实际产物、正确性、性能、整体耗时及可获取的 token/调用/设备消耗；未知值保持未知 |
| 现有对照评测尚未覆盖新增 NPU 任务 | 调用方控制变量并重复执行，利用同一格式的记录分析效果与代价 |

评测层不需要理解调用方切换的是 indexer、Agent 还是知识库；它保存配置身份和真实结果。整体实验的设计、重复安排与归因沿 [#248](https://github.com/InferMatrixLab/InferRSI/issues/248) 或调用方的职责进行，不在这里另建组件实验平台。并行搜索与优化策略仍有独立范围。

## 流程与独立验收

目标链路是：**提供任务和运行条件 → Agent 自主优化 → 留存实际产物 → 工具独立验收 → 效果与消耗报告。** Agent 在允许的工具和预算内自行选择方法；profiling 保留为可选工具，不是必做步骤，也不因没有 profile 默认判失败。

独立验收来自具体任务的测试与 benchmark，不是万能裁判。题库任务预先提供这些内容；外部项目优先复用项目自身测试，必要时补充专项检查，并在优化前固定输入、质量规则、测量条件和允许修改范围。比如 vLLM 优化，要按实际目标检查改动语义、模型质量及固定负载性能；单个算子变快不能代替模型或服务验收。当前工具不会自动从任意一句目标生成可靠裁判。
