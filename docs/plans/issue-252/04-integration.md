## 流程也是交付内容

1. **准备任务。** 接收内置题包，或外部项目的仓库、基线、允许修改范围、工作负载、测试和 benchmark。缺少可靠验收方法时先补齐，不能凭目标文字生成成功判定。
2. **记录运行条件并启动。** 复用已有入口保存任务、Agent/RSI 配置、版本、环境和预算；保留实际执行记录。
3. **Agent 自主优化。** 在允许的工具和预算内选择方法、修改和测试，可以尝试多个候选。
4. **留存实际产物。** 保存最终代码及其身份、过程和失败记录，不能替换成预写参考候选。
5. **独立验收。** 工具按执行前确定的规则检查实际产物，并在固定条件下重测基线与候选。结论不采用 Agent 自报的加速数字。
6. **汇总效果与消耗。** 将正确性、性能、实际执行状态、时间和可获取用量关联，生成可追溯记录。

Profiling 是可选诊断，不是通用必做步骤，不因没有 profile 默认判失败，也不要求另行说明或申请跳过。只有具体任务在执行前明确要求诊断产物时，才检查该项。已经完成的 NPU 工具资格试点仍保留原冻结的 profiling 检查和证据。

评测层不识别 indexer、知识库开关等组件语义。调用方负责切换条件、控制变量、重复执行和解释差异；本项保存配置身份、实际产物与统一结果。普通用户优化一次任务不需要额外运行对照 Agent。

## 外部项目怎样独立验收

以 vLLM 项目的一次优化为例，调用方先明确目标、模型、输入、硬件和工作负载，优先复用项目已有测试与 benchmark，必要时增加专项检查。改动语义、模型质量和目标性能按任务要求分别检查；算子级结果不能代替模型或服务结果。验收规则、容差和输入不随候选一起降低。

本项提供产物交接、执行、身份和结果关联，不提供适用于所有项目的万能 oracle，也不承诺把任意自然语言目标自动转为可靠验收方案。首轮外部目标应有明确、可复现的质量检查和 benchmark，再按实际选择完善适配。

## 首轮完成条件

- [ ] 一种真实 Agent 从受支持入口完成内置 `rmsnorm-npu` 任务，实际代码被留存并由独立工具重验；不得回放预写 reference 充当 Agent 产物。
- [ ] 一个选定的外部项目 NPU 目标复用自己的测试与 benchmark，进入同一结果与消耗记录链路；项目、模型与 workload 在执行前确定。
- [ ] NPU 产物执行边界、任务/候选版本绑定、单次与整轮预算、中断清理有相应检查；缺环境与失败保留原因。
- [ ] 缺失产物、错误结果、超时或不完整测量不能被记录成优化成功；profiling 未调用不是默认失败原因。
- [ ] 实际重复执行并保留全部记录，验证效果与代价可对照；缺失 usage/费用保持未知，不伪造精确总成本。
- [ ] 文档说明已有入口如何调用、输出如何解释以及如何接外部任务；实现和验收证据随同后续 Draft PR 交付。

重复次数、模型、预算与性能门槛属于具体实验计划，执行前固定，不在本页添加仓库默认值。一个任务没有取得改善可以是完整的负结果；工具可靠性与 RSI 收益是不同结论。
