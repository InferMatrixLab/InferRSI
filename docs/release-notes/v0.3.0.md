# InferRSI v0.3.0

InferRSI v0.3.0 ties optimization decisions to measured bottlenecks. Teams can now run the same task with the knowledge library enabled and disabled, then compare the candidates that two independent agent sessions produce within the same budget. These highlights cover changes since v0.2.0.

## Optimization and evaluation

- **Diagnose the bottleneck before searching.** New managed optimization runs record a baseline profile or measurements from the same workload and environment before the agent searches for knowledge or evaluates a candidate. Each round links back to its diagnosis. Project campaigns can also start one service per candidate and use it for performance, quality and optional profiling checks. The selected candidate gets an independent final evaluation. [Diagnosis](https://github.com/InferMatrixLab/InferRSI/pull/519) · [Service reuse](https://github.com/InferMatrixLab/InferRSI/pull/480) · [Optional profiling](https://github.com/InferMatrixLab/InferRSI/pull/521)
- **Measure what the knowledge library contributes.** `inferrsi benchmarks compare` runs independent optimization sessions with managed knowledge on and off under the same task, evaluation rules and round budget. It defaults to Qwen-Image 2.1 denoising and MoE forward on Ascend. The report pairs final speedup with elapsed optimization time and flags missing or invalid pairs as insufficient evidence. [Comparison guide](https://github.com/InferMatrixLab/InferRSI/blob/6ed42af83a69f13fe88aaf0426ab8ef4f8ac7654/docs/benchmark-comparison.md)

## Knowledge and results

- **Start from the engineering task.** Seven entry points cover model bring-up, performance, debugging, accuracy, version alignment, derived engines and independent engines. Search spans skills, cases and engineering findings. With CANNBot enabled, the dashboard shows its search and read records alongside local retrieval and identifies the sources the agent explicitly cited in each round. [Task routes](https://github.com/InferMatrixLab/InferRSI/pull/516) · [CANNBot tracing](https://github.com/InferMatrixLab/InferRSI/pull/523)
- **Review and share a run.** The dashboard connects performance trends to individual rounds, candidate choices and execution results. `inferrsi export` writes a Markdown report, offline HTML, a machine-readable result and an artifact index from the same snapshot. Keep the original campaign directory for the code and evidence referenced by the export. [Round view](https://github.com/InferMatrixLab/InferRSI/pull/495) · [Result export](https://github.com/InferMatrixLab/InferRSI/pull/485)
- **Revisit earlier experiments.** Versioned archives preserve the original trial records for H3 Ref2VA, Qwen3.8 and MiniCPM Seed-TTS. The repository keeps compact evidence bundles with checksums, so reviewers can inspect individual trials and their original verdicts. [H3 and Qwen3.8 archives](https://github.com/InferMatrixLab/InferRSI/pull/472) · [MiniCPM Seed-TTS archive](https://github.com/InferMatrixLab/InferRSI/pull/435)

## Upgrading from v0.2.x

The `inferrsi` command and `python -m inferrsi` remain the CLI entry points. Apps now brings together the CLI, integrations and reports. Harness runs experiments, Benchmark owns tasks and evaluation rules, and Knowledge supplies skills and findings. Python integrations that import the retired `inferrsi.infra` or `inferrsi.model` packages need to update those imports. [CLI migration](https://github.com/InferMatrixLab/InferRSI/pull/461) · [Full module migration details](https://github.com/InferMatrixLab/InferRSI/blob/6ed42af83a69f13fe88aaf0426ab8ef4f8ac7654/CHANGELOG.md)

| Previous import | v0.3.0 import |
| --- | --- |
| `inferrsi.cli` | `inferrsi.apps.cli` |
| `inferrsi.infra.artifacts` | `inferrsi.apps.artifacts` |
| `inferrsi.infra.http` | `inferrsi.harness.serving.http` |
| `inferrsi.model.protocols.metrics` | `inferrsi.benchmark.metrics` |
| `inferrsi.model.validators` | `inferrsi.benchmark.validators` |

**Keep the original runtime for in-flight sessions.** A frozen plan records the runtime that created it. Use that environment for `status` and `recover`. Start a fresh session to run under v0.3.0. [Session recovery guide](https://github.com/InferMatrixLab/InferRSI/blob/6ed42af83a69f13fe88aaf0426ab8ef4f8ac7654/docs/optimization-workflow-unification.md#release-boundary-recovery)
