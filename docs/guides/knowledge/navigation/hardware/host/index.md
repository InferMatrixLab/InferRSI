# HOST sources

Read the original for its device, release and verification boundaries.

- [`package:inferrsi.common.skills.cgroup_resource_controls`](../../../../../../src/inferrsi/knowledge/data/skill_library/systems/platforms/host/cgroup-resource-controls/SKILL.md) — Diagnose and configure cgroup v2 resource controls for serving/training workloads: distinguish quota stalls from sibling contention (cpu.max vs cpu.weight, cpu.stat vs cpu.stat.local), audit requested-versus-effective cpuset with migration-cost budgeting, triage memory pressure with PSI plus event deltas (high/max/low semantics), and gate io.max caps on confirmed block-backed traffic. Includes hierarchy/delegation/permission preflight and a rollback contract. Extra resource allocation is treated as a capacity spend, never as an efficiency improvement. Control-plane procedures only — applying settings requires separate authorization.
- [`package:inferrsi.common.skills.host_memory_management`](../../../../../../src/inferrsi/knowledge/data/skill_library/systems/platforms/host/host-memory-management/SKILL.md) — Audit pinned host buffers and asynchronous CUDA transfers: distinguish copy ordering, host mutation/reuse and device allocator lifetime; use bounded PyTorch source evidence, a reusable staging-slot example and a hardware validation recipe. Also route Ascend native descriptor retention, Python preprocessing and NUMA placement to their scoped sources.
- [`package:inferrsi.common.skills.host_overhead_optimization`](../../../../../../src/inferrsi/knowledge/data/skill_library/systems/platforms/host/host-overhead-optimization/SKILL.md) — Profile and reduce CPU/host overhead in inference serving using line_profiler. Iterative profile-analyze-optimize-validate loop targeting Python execution in request preparation, scheduling, and model execution coordination.
- [`package:inferrsi.common.skills.os_process_placement`](../../../../../../src/inferrsi/knowledge/data/skill_library/systems/platforms/host/os-process-placement/SKILL.md) — Place and configure inference/training processes at the OS level before measuring or optimizing: check then pin CPU affinity to the accelerator-local NUMA node (taskset/numactl), keep affinity constant across measurement rounds, set thread-count environment variables (OMP_NUM_THREADS, OMP_PROC_BIND, CPU_AFFINITY_CONF) per scenario, run a device-busy preflight (npu-smi/nvidia-smi usages, graceful-then-force PID cleanup), and structure environment checks as ERROR vs WARNING with per-failure remediation. Use before any performance measurement on shared multi-socket or multi-tenant hosts. Does not cover cgroups, cpuset, isolcpus, or scheduler priorities — no source evidence for those.
- [`package:inferrsi.common.skills.storage_io_measurement`](../../../../../../src/inferrsi/knowledge/data/skill_library/systems/platforms/host/storage-io-measurement/SKILL.md) — Measure storage I/O for LLM/diffusion serving without conflating device metrics with application outcomes: match the fio workload to the observed loader signature, validate requested-versus-achieved I/O depth, keep a cache-state ledger (warm/cold/unknown with method), classify startup vs steady-state runs, read outputs with unit and latency-provenance awareness, attribute traffic per device (iostat) and per process (pidstat), and gate any "storage bottleneck" claim through a saturation-evidence check plus a separate application-outcome layer. Measurement methodology only — running benchmarks or manipulating caches requires separate authorization.
