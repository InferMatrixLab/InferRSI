# Research-boundary diagnostics

| Symptom | Distinguish | Safe next step |
| --- | --- | --- |
| A product-page number is treated as a local result | Reported versus reproduced evidence | Retain attribution and request the bounded raw artifact/identity bundle |
| A future direction appears as shipped capability | Proposal versus implementation observation | Keep it in the proposed class until source/runtime evidence supports it |
| A plausible mechanism is called the root cause | Explanation versus discriminating observation | State a counter-explanation and a falsifier before experimenting |
| A negative example is used as a permanent blacklist | Local disposition versus changed conditions | Record applicability and the condition needed for a justified revisit |
| Discarded samples disappear from the conclusion | Selection rule versus retained evidence | Preserve the exclusion reason and unavailable raw-data gap |
| A consistent JSON card is called authentic evidence | Schema consistency versus observed bytes/execution | Keep qualification unadjudicated; authenticate artifacts separately |
| A source hash or repository identity is guessed | Extraction view versus original/versioned source | Mark it unknown; do not label a rewritten summary as raw page bytes |
| A source/license lookup is unavailable | No usable query result versus no legal license | Preserve UNKNOWN and the resolver warning; infer no redistribution rights |
| A synthetic test is used to clear native correctness | Guidance test versus engine/model/backend behavior | Keep native/reproduction gaps explicit and stop the dependent claim |

The official source view is unversioned. A failed direct retrieval does not
authorize access-control bypass, impersonation, app installation or account
creation. Use available authorized public material, state the limit and request
missing evidence only when the selected question needs it.
