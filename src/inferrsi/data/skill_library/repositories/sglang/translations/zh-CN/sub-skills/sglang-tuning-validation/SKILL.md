# 调优与验证

读取[调优与验证](../../references/tuning-and-validation.md)，获取命令、测量设计、失败恢复及本地/GPU 门槛。[返回根路由](../../SKILL.md)。

搜索前写明目标和硬约束，例如：在 p99 TTFT/ITL、错误预算、准确性容差和显存容量约束下提高已完成请求吞吐。明确负载分布及有限的轮数/时间预算。一次随机输入吞吐得分不足以得出生产结论。

将每个候选标为现有参数、实现修改或研究扩展。从可复现基线出发，先改变一个因果类别，再探索已观测到的交互。消耗 GPU 时间前，通过源码校验规则排除无效组合。

成对实验保持模型/tokenizer、提交、拓扑、请求集、到达过程、seed、缓存策略、输出上限/EOS 行为、预热和测量时长一致。收集成功/失败请求、排队、token 数、p50/p95/p99 延迟、吞吐、内存余量，以及可用的缓存/投机统计。

排序前先通过正确性门槛：数值参考和 logits/logprobs；cache miss/hit；分块/不分块；投机/基线；目标分布式拓扑；代表性质量检查。容差由参考路径和 dtype 决定，不能不断放宽到候选通过为止。

拒绝违反约束的候选。对有希望的成对配置重复测量以暴露方差，保留失败和原始产物，并报告 Pareto 权衡。达到预设预算或效果低于噪声时停止。环境无法执行必要门槛时，交付可运行的验证计划，并将该门槛标为未验证。
