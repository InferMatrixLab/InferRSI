# Runtime and invariants

## A V1 iteration

The concrete `EngineCore.step` calls `scheduler.schedule`, submits `execute_model`, samples if needed, processes aborts that arrived during execution, then calls `update_from_output`. The batch-queue path is adjacent and must be inspected for asynchronous overlap. A conceptual frontend → engine → scheduler → runner map is useful, but changes must follow the selected executor and model-runner implementation. [engine](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/v1/engine/core.py#L657-L687)

The scheduler models outstanding work as `num_tokens_with_spec` versus `num_computed_tokens`, rather than two disjoint prefill/decode schedulers. Prompt, generated and draft tokens contribute to this accounting. At this snapshot, `token_budget` comes from `max_num_scheduled_tokens`, while `input_budget` comes from `max_num_batched_tokens`; drafting reserves additional slots. Output placeholders also affect outstanding work. Do not model batch capacity with a single token count when speculation or async execution is enabled. [sched](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/v1/core/sched/scheduler.py#L591-L628) [budget](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/v1/core/sched/scheduler.py#L703-L721)

`max_num_seqs` sizes runner capacity; `max_num_active_seqs` may lower RUNNING admission without shrinking runner/graph capacity. `max_num_queued_reqs` instead bounds API-server in-flight requests across the DP ranks it routes to. These limits solve different problems. Dataclass defaults are explicitly for testing convenience and can be set by EngineArgs. [sched_config](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/scheduler.py#L48-L103)

Scheduling also requires KV allocation. Allocation failure may preempt a running request, but deferred connector frees cannot be treated as immediately reusable blocks. A priority policy and FCFS choose victims differently. At the end, the code checks scheduled tokens, nonnegative token/input budgets and the admitted running-request bound. A policy change must preserve those checks and make progress under memory pressure. [preempt](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/v1/core/sched/scheduler.py#L775-L857) [invariants](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/v1/core/sched/scheduler.py#L1403-L1415)

## KV allocation, identity and lifetime

`KVCacheManager` coordinates cache groups, prefix lookup and allocation; `BlockPool` owns physical-block reuse and reference counts. A cache hit is not free memory: touching a reusable block removes it from the eviction queue when necessary and increments its reference count. Releasing a request can return blocks to the free queue only after references reach zero, with a special null-block case. Shared cache content and writable tails need separate reasoning. [kv_hit](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/v1/core/kv_cache_manager.py#L249-L321) [kv_alloc](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/v1/core/kv_cache_manager.py#L371-L470) [kv_lifetime](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/v1/core/block_pool.py#L666-L795)

Prefix identity includes the parent prefix, tokens, and extra hashes such as LoRA identity, multimodal content and cache salts. Text similarity alone is not cache equivalence. Salt can bound reuse to a trust group. The default hash uses SHA-256 with Pickle serialization; `sha256_cbor` uses canonical CBOR for cross-environment reproducibility. Cache reuse must be invalidated when its semantic inputs, including weights, change. [prefix](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/docs/design/prefix_caching.md#L15-L31) [salt](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/docs/design/prefix_caching.md#L84-L100)

Do not universalize the older design note's “full blocks” sentence to every current physical KV group. Current `prefix_match_unit` controls hash/match granularity and may be smaller than physical blocks; it must divide group block sizes. For hybrid Mamba, matching granularity alone does not store intermediate states. The shared-prefix checkpoint feature has additional conditions (prefix cache, Mamba EAGLE/MTP, finer match unit and no multi-module MTP); inspect the selected model/group implementation. [cache_match](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/cache.py#L74-L100) [hybrid](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/docs/features/automatic_prefix_caching.md#L15-L38)

## Paged KV versus actual attention kernels

Paged storage maps logical token positions to physical KV blocks; the selected kernel must honor the resulting layout, block tables, query lengths and supported dtype. The repository's old PagedAttention design document explicitly warns that it no longer describes current code. Use it only for historical intuition. [paged_history](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/docs/design/paged_attention.md#L1-L13)

Current `get_attn_backend` constructs a selector from head size, model/KV dtype, requested block size, MLA/sparse/sliding-window features, KV transfer, context parallelism and other capabilities. It delegates to the platform and supports per-cache-kind overrides. A kernel present in the tree may not be selected for this model. Verify startup selection and profile the actual path before optimizing a historical CUDA kernel. [attention](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/v1/attention/selector.py#L105-L225)

## Parallel and transfer ownership

TP partitions tensor work, PP partitions stages, DP replicates/routes request work, and EP distributes MoE experts instead of tensor-sharding those layers. Current PCP adds a process axis; ordinary non-external process topology is TP × PCP × PP per DP replica. The config also has external-launcher handling, so verify its rank arithmetic rather than multiplying blindly. DCP reuses the TP ranks when PCP=1 and requires TP divisibility; with PCP enabled, allowed DCP sizes are constrained to 1, PCP or TP×PCP. MoE sharding also involves TP×PCP×DP. [parallel](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/parallel.py#L139-L163) [world_size](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/parallel.py#L946-L965) [context_parallel](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/parallel.py#L591-L629) [ep](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/parallel.py#L189-L233)

P/D separation runs prefill and decode in different instances and transfers KV through a connector. Scheduler hooks plan matched tokens/allocation and produce metadata; worker hooks start/load/save and synchronize transfers. Completion can delay block release until an asynchronous transfer finishes. Preserve exact token/model/layout compatibility and honor the selected connector's compatibility matrix. `kv_load_failure_policy` currently distinguishes `fail` (default) from `recompute`; fallback must be intentional and observable. [pd](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/docs/features/disagg_prefill.md#L1-L33) [connector](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/distributed/kv_transfer/kv_connector/v1/base.py#L1-L41) [connector_finish](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/distributed/kv_transfer/kv_connector/v1/base.py#L371-L408) [kv_transfer](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/kv_transfer.py#L56-L91)
