# Existing controls versus new capabilities

Read this before calling a tuning result an engine innovation. A supported flag changes an existing policy or implementation; a new capability needs a missing behavior, an owned code path, invariants and a measurable advantage over existing controls.

| Mechanism | Existing search space at this snapshot | What would require implementation or new evidence |
|---|---|---|
| Token/admission scheduling | Runner input `max_num_batched_tokens` and the separate effective `max_num_scheduled_tokens` budget; `max_num_seqs`, `max_num_active_seqs`, long-prefill threshold, policy/async configuration | A new fairness/SLO policy, budget model, or admission state transition; prove no starvation, budget violation or stale output |
| KV/prefix reuse | prefix enablement/hash/match unit, cache dtype, byte budget, supported offload | New cache identity, eviction, storage granularity or hybrid checkpoint semantics; prove isolation, reference lifetime and exact semantic reuse |
| Speculation | supported method, draft model, draft count, compatible draft TP | New proposer/verifier integration or acceptance policy; prove target sampling behavior and KV rollback, then measure net benefit |
| Parallelism | TP/PP/DP/EP, PCP/DCP, communication backend and supported load balancing | New partition/collective/layout or scheduler topology; prove rank groups, weight mapping, collective order and model support |
| P/D and external KV | registered connector and role/configuration | New transport or lifecycle semantics; prove load/save readiness, delayed release, abort and partial failure |
| Compilation/kernels | supported compile/graph modes, capture sizes, attention selection and quantization formats | New lowering/fusion/kernel/backend/quant format; prove shape/layout/numerical behavior and dispatch before timing |

## Distinctions that prevent invalid proposals

- **Paged KV is a storage/ownership mechanism; prefix caching is a reuse policy.** Improving one does not automatically improve the other. A longer-lived cache also competes with active requests for memory.
- **Compile and CUDA graphs are separate axes.** `CompilationMode` and `CUDAGraphMode` have different contracts. Piecewise graphs require compatible piecewise compilation; full graphs can exist with or without compilation. Capture shapes consume memory and affect warmup/startup. [compile_mode](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/compilation.py#L37-L69) [graphs](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/compilation.py#L610-L654)
- **Weight quantization and KV quantization solve different memory costs.** A format string in the registry is not universal kernel/model/hardware support. Check checkpoint layout, backend support, scale handling and accuracy under the actual workload. [quant](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/model_executor/layers/quantization/__init__.py#L15-L114) [quant_docs](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/docs/features/quantization/README.md#L25-L99) [cache_config](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/cache.py#L102-L155)
- **Speculation has draft, target-verification and scheduler costs.** Net benefit depends on acceptance length and offered load, not just proposed tokens. Standard rejection logic distinguishes accepted, recovered and bonus tokens. Synthetic acceptance controls are for controlled performance studies and cannot establish target-output correctness. [rejection](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/v1/sample/rejection_sampler.py#L46-L71) [synthetic](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/vllm/config/speculative.py#L529-L549)
- **P/D is an SLO/topology decision.** Compare against tuned chunked prefill, include transfer and proxy cost, and do not claim inherent throughput improvement. The pinned feature guide explicitly cautions against that claim. [pd](https://github.com/vllm-project/vllm/blob/2521446ac8c92937b5a32b7dc2a84ef7fa8e99c5/docs/features/disagg_prefill.md#L1-L33)

For a novel proposal, deliver: (1) which existing controls fail and how measured; (2) specific missing behavior and owner; (3) invariant-preserving implementation sketch; (4) discriminating workload and baseline; (5) rejection conditions. Label any expected speedup as a hypothesis until measured.
