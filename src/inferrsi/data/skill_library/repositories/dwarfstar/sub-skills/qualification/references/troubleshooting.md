# Qualification troubleshooting

| Observable symptom | Likely contract to inspect | Concrete next check/recovery | Stop boundary |
| --- | --- | --- | --- |
| Plausible draft acceptance but degraded continuation | Target/support checkpoint mismatch or a changed sampling mode | Record exact target/support hashes and family; compare target-only, opportunistic and exact modes separately; inspect first divergence and full quality output | Missing matched support file or quality validator; do not download/convert automatically |
| Same seed gives different output under exact sampling | Extra accept/reject random draws; batched verifier arithmetic | Check the promised invariant: filtered distribution and state/quality, not identical RNG consumption across different algorithms | Do not redefine a frozen exact-byte gate after observing a difference |
| High acceptance but no speedup | Draft/verifier/commit/replay cost or transport/cache pressure exceeds saved decode | Break out phase times, accepted length and replay/correction counts; compare unpredictable as well as predictable prompts under identical controls | No complete timing/quality evidence means no gain claim |
| `speculative decode requires a synchronized checkpoint` | Token history and live graph frontier are not valid together | Invalidate/rebuild through the owning session path; retain cancellation/restore context and check the continuation after synchronization | Do not force the validity bit or truncate only the token vector |
| Error after tool syntax begins, or repeated long-context replay | Speculative block crossed a sampling-mode boundary; recent frontier restore unavailable | Preserve trace of kept/discarded rows and resampling mode; distinguish recent exact rewind from stale rewind/rebuild | Real recurrent/kernel restore needs the actual backend; CPU assertions cannot clear it |
| V4.1 restore initially produces no drafts | Saved target caches do not include a complete draft-feature window | Record ordinary warm-window decoding and subsequent eligibility; compare steady-state separately from restore cost | Do not invent missing draft features or call the warmup a speculation failure |
| V4.1 network DSpark appears accepted by code but a guide says unsupported | Conflicting revision-local documentation and model-specific implementation paths | Keep the conflict explicit and request revision-specific native both-rank evidence for the exact transport/checkpoint/mode | Without that evidence the capability remains unverified, not definitely supported or definitely absent |
| CUDA network TP rejects SSD streaming or local CUDA TP options | Mutually exclusive placement modes | Select one mechanism: local pairing, resident two-rank network TP, or pipeline; recompute its budget and workload | Do not remove the validator to make an unsupported combination start |
| `tp hello` version/role/model mismatch | Peers disagree on protocol, complementary roles, model/layout or gate schedule | Check same source/build intent and matched artifact identities on both peers; repair the declared configuration | Hello metadata agreement is not model-byte integrity; do not bypass checks |
| TCP succeeds, RDMA stalls or silently falls back | Device/GID/link/runtime not qualified or transport negotiated differently | Preserve both logs, negotiated transport and device/link status; use explicitly selected TCP only when the changed experiment scope is accepted | Ping/local loopback is not RDMA evidence; no automatic network or privileged host changes |
| Peer timeout or failed verify commit | Route or mirrored frontier is invalid | Retain the failure, invalidate every affected session, restore a complete route and replay a valid saved prefix before new work | A retry that later succeeds does not erase the failed trial |
| Parser/protocol tests pass; deployment still fails | CPU framing checks do not execute kernels, real network, model or service workload | Follow the proof ladder in the verification contract; report each passed/failed/not-run layer separately | Missing physical/native evidence remains `BLOCKED_REQUIRED_BACKEND`; candidate admission needs informed acceptance |

Do not publish raw prompts, tool traces, peer addresses or user paths while
diagnosing. Keep logs task-owned and redact before sharing without changing
failure status or the experimental conclusion. Do not terminate or signal an
unidentified process; physical failure injection needs its own authorized scope.
