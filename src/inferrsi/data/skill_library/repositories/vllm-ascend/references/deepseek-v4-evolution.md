# DeepSeek-V4 support and performance evolution

Use this procedure with the v0.27.1rc1 source and record model variant, weight revision, runner generation, device profile, cache plan, TP/DP/CP layout, speculative method and workload phase. The RC release qualification covers DeepSeek-V4-Flash on 950DT in its declared W4A8C8 PD scenarios. Earlier A2/A3, Pro and V2 changes below supply implementation history and diagnostic mechanisms. Validate their actual combination separately. [Release scope](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/docs/source/user_guide/release_notes.md)

## Follow the implementation lineage to the active path

Initial support joined the V4 model, MTP, DSA metadata/backend, compressed cache groups, quantized loading and hybrid KV transfer. Its monolithic attention and model paths later split into the tag's `models/deepseek_v4/` modules. The Ascend950 integration added a distinct device operator plan. When locating an optimization, trace the installed caller through the tag's model → DSA backend → compressor/indexer → concrete operator rather than applying a historical path mechanically. [7bce23cc0](https://github.com/vllm-project/vllm-ascend/commit/7bce23cc0572a7793636ae215015a528e4503f1e), [fcb30bebe](https://github.com/vllm-project/vllm-ascend/commit/fcb30bebed4bc493238f2c432844b1f1be16ae6d), [tag model](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/models/deepseek_v4/model.py)

The initial `hc_pre` v2 switch was reverted for correctness and later restored after synchronization with the fused implementation. Before substituting a fused call, verify its argument layout, Sinkhorn iterations and epsilon values against the checkpoint and matching operator package. Compare intermediate/output tensors and a representative model task before using kernel duration as a success criterion. This history makes the later fix part of the optimization's required provenance. [d31c223a8](https://github.com/vllm-project/vllm-ascend/commit/d31c223a8b74a0367ce4946c9053b6abb15d1e32), [c1be5934e](https://github.com/vllm-project/vllm-ascend/commit/c1be5934e36d0afd448bca5d2eef5a5ccd8de981), [baf4a9d0b](https://github.com/vllm-project/vllm-ascend/commit/baf4a9d0bd1e6432ed799b0d1ee16c7ebe73a5a0)

## Select the attention cache plan before comparing kernels

1. Record the hardware profile's `DSV4_COMPRESSED_CACHE` capability and the *explicit* cache request. In the tagged resolver an explicit `bf16`/`bfloat16` request on the capable path preserves BF16 mode. `auto` selects the FP8 attention plan on that path. The effective dtype depends on this request even when model weights are BF16.
2. Trace all coupled fields. The BF16 plan uses SparseFlashMla, `PA_BBND`, two-column block/offset slots and scatter updates. The FP8 plan uses the quantized sparse-attention operator, `PA_ND`, flat slots and `kv_compress_epilog`. The indexer retains its separate FP8 representation. Changing only the attention operator or only the dtype leaves an inconsistent allocation/metadata path.
3. Check dependency availability in the actual worker. The SparseFlashMla loader requires `cann_ops_transformer` and its two operator registrations, and its error names a matching CANN 9.2 toolkit. The release table lists CANN 9.1.0 for its release images. Resolve the supplied operator package and selected plan experimentally before declaring that pair compatible.
4. For graph execution, preserve fixed `[T,2]` slot storage and padded `[-1,-1]` rows on the BF16 path. The tagged code avoids a data-dependent nonzero/gather when scattering. Use `test_dsa_attn_kv_plan.py`, `test_sparse_flash_mla.py` and `test_dsv4_block_geometry.py` to locate dtype, layout, padding and slot-format oracles, followed by real NPU numeric checks.

The BF16-plan integration and the tag's centralized plan retain these coupled choices. [8db29fde7](https://github.com/vllm-project/vllm-ascend/commit/8db29fde7ec642061230048db696ce74106d2142), [vllm_ascend/attention/dsa_attn_kv_plan.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/attention/dsa_attn_kv_plan.py), [vllm_ascend/attention/sparse_flash_mla.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/attention/sparse_flash_mla.py)

## Diagnose metadata latency and ordering together

The first device-metadata stage moved compressor metadata construction into a device operator. The later V1 implementation collects compressor, indexer and attention tasks and submits them on a worker-owned stream. It records input readiness, waits on buffer reuse from the previous forward, orders tasks by stage and exposes group-specific consumer events. Full-graph batches use persistent external events indexed by batch descriptor and reject changed stage/group frontiers. [vllm_ascend/worker/device_metadata.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/worker/device_metadata.py), [53f698ff7](https://github.com/vllm-project/vllm-ascend/commit/53f698ff7a48ce1f2b6c6ae5d26811883001bcd5)

1. Establish that the active metadata builder implements `DeviceMetadataTaskProvider`. Record the actual tasks taken from each builder. A source-level optimization can be bypassed by a different runner, backend or branch.
2. In the trace, correlate metadata submission, the compressor/indexer/attention consumer waits and `release()`. Persistent output storage is reusable only after the forward releases it. If submission raises partway, the executor retains in-flight state. Treat that state as requiring controlled recovery before another submission.
3. For full graph, compare the batch descriptor, stage/group keys, output addresses and event wait/reset sequence. For compressor metadata, distinguish the capture bucket's extent from the active-request extent. For draft SWA metadata, check the preallocated output capacity and whether the batch is decode-only.
4. Profile operator time plus consumer wait time. Moving work to another stream can hide its latency only when independent compute is available. Keep correctness, useful overlap, metadata launch count and end-to-end latency as separate measurements.
5. Retain the late QLI correction. The tag derives local query lengths from the device `query_start_loc` and reads the maximum with `.item()` because the CPU copy can diverge under async scheduling. A CPU-only replacement requires a proof that its metadata describes the same consumer step. The presence of this sync is an explicit correctness tradeoff in the selected release.

Use `test_stream_lifecycle_and_stage_frontiers`, `test_external_event_frontiers_must_remain_stable`, `test_submit_failure_keeps_partial_submission_in_flight`, and `test_wait_uses_group_specific_frontier` in the executor tests. The DSA tests cover fixed output storage and full-graph compressor extents. [tests/ut/worker/test_device_metadata.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/worker/test_device_metadata.py), [tests/ut/attention/test_dsa_v1.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/attention/test_dsa_v1.py), [93b794254](https://github.com/vllm-project/vllm-ascend/commit/93b7942540c53d8d4486c2cc4579f356f520d0e0)

DSA-CP's local metadata optimization fuses request-boundary clipping, cumulative local query lengths, local sequence lengths and optional start positions in a Triton kernel. Verify empty rank slices, padded requests and RoPE padding when comparing it to a tensor-op implementation. Later SP integration changes which tensor is local and when full KV inputs are gathered, so use the current layout contract with the fused metadata. [84c647f19](https://github.com/vllm-project/vllm-ascend/commit/84c647f198944ccdd306eb196d35e59c1e2b70c5), [78bf96a55](https://github.com/vllm-project/vllm-ascend/commit/78bf96a55bc91466eae7ac5fe080596fac7b9d5a), [vllm_ascend/ops/triton/dsa_cp.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ops/triton/dsa_cp.py)

## Preserve compressor and indexer dependencies while overlapping work

The c4 path can overlap main-attention compressor work with indexer query/cache preparation. In the tagged modular indexer, the main stream's projection and Hadamard work runs alongside auxiliary quantization/cache scatter, and top-k selection waits for its metadata frontier. On A5, the fused indexer compression epilog handles key and scale cache together, removing the separate scale-cache scatter stage. Inspect the selected hardware implementation before interpreting a missing stage as a defect. [20e338bd7](https://github.com/vllm-project/vllm-ascend/commit/20e338bd7c1267799dcf611acee025f37cdc9535), [vllm_ascend/models/deepseek_v4/indexer.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/models/deepseek_v4/indexer.py)

If multistream performance regresses, capture the main/aux event sequence, dtype conversions and each cache write's consumer. Compare serial and overlap paths on the same prefill/decode mix and compression ratio. A2/A3 history explicitly preserves FP32 RoPE tables for compressor/rotation precision. Keep that choice when investigating an apparent cast or bandwidth saving. [77e1e1fc6](https://github.com/vllm-project/vllm-ascend/commit/77e1e1fc6430b166abd4715271bf55f817b38630), [vllm_ascend/models/deepseek_v4/compressor.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/models/deepseek_v4/compressor.py), [vllm_ascend/ops/rope_dsv4.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ops/rope_dsv4.py)

## Use IndexCache with its layer and buffer contract

`use_index_cache`, `index_topk_pattern` and `index_topk_freq` choose which c4 indexer-bearing layers reuse the previous selected top-k. The implementation excludes `.mtp.` layers because their implementation-level references can be stale. An explicit pattern must begin with `F`; `S` marks a reuse layer. Inspect the generated layer decisions and shared buffer before changing the frequency. The old commit title mentions decode steps, but the source mechanism reuses top-k across selected layers within the current computation. [711a09f73](https://github.com/vllm-project/vllm-ascend/commit/711a09f73305847f22f9ad062c5e317837f4a26f), [vllm_ascend/models/deepseek_v4/model.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/models/deepseek_v4/model.py)

For a quality or stale-index regression, inspect which layer last wrote the buffer, token count, head dimension and decode/prefill slice. The modular indexer validates a singleton head dimension when squeezing into its shared storage. DSA-CP gained its own skip branch and refresh on full indexer layers later. A valid control is the same checkpoint/workload with index reuse disabled, measuring output quality alongside removed indexer work. A reduction in indexer calls alone leaves the model-quality effect unresolved. [45e0634c1](https://github.com/vllm-project/vllm-ascend/commit/45e0634c1ba2ccbc400cc2167009a11b687d74ef), [vllm_ascend/models/deepseek_v4/indexer.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/models/deepseek_v4/indexer.py), [vllm_ascend/attention/context_parallel/dsa_cp.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/attention/context_parallel/dsa_cp.py)

## Keep scheduler geometry, physical pages and reuse layout consistent

The compression-specific cache manager was removed. At the tag, the scheduler block represents original tokens and `storage_block_size = block_size // compress_ratio` determines physical rows. The cache spec calculates physical bytes with storage size, while logical capacity uses scheduler block size. Audit the spec, block table, compressor slot mapping and connector as one path before changing block size. Reusing an older formula that divides block counts by the compression ratio again can under-allocate or misaddress cache. [749bb6c82](https://github.com/vllm-project/vllm-ascend/commit/749bb6c82d2aed0d54f7eb898f33ea5a8169ba2e), [vllm_ascend/core/kv_cache_interface.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/core/kv_cache_interface.py), [tests/ut/attention/test_dsv4_block_geometry.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/attention/test_dsv4_block_geometry.py)

For prefix-hit regressions, inspect all groups. The historical write/read retention mismatch for EAGLE/MTP required propagating `use_eagle` to same-spec siblings, because the read path merged them and the hybrid hit was bounded by the least reusable group. Preserve this failure pattern when comparing cache hit rates at different block sizes. [cadefd2cb](https://github.com/vllm-project/vllm-ascend/commit/cadefd2cb87a8b0dc6d4e80abc2d770121a92f42), [tests/ut/patch/platform/test_prefix_cache_cp_patches.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/patch/platform/test_prefix_cache_cp_patches.py)

For layerwise KV Pool reuse, enumerate every cache spec per physical layer. V4 can expose attention, indexer, compressor state and SWA caches. The RC layout selects `.attn` as main, retains other main specs in `extra_main_specs`, and keeps an optional indexer. Test both five-spec V4 layers and the old one-main/one-indexer case. A successful layout construction needs subsequent transfer/reuse evidence before claiming a serving improvement. [79044c436](https://github.com/vllm-project/vllm-ascend/commit/79044c4369e3f30ef86e6042952a3c9ee8a8dd13), [tests/ut/kv_transfer/test_layerwise_multi_cache_spec.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/kv_transfer/test_layerwise_multi_cache_spec.py)

## Match DSpark execution to its own query and collective shape

The V4 DSpark integration prepopulates draft KV from target hidden states and executes a block of queries. The V1 proposer allocates hidden storage from the draft model and disables draft graph use. Its query width is K when `sample_from_anchor` is true and K+1 otherwise. The tag also contains a V2 speculator with a full-graph manager and padded query metadata, so record the runner before selecting an oracle or interpreting a graph log. [8fe122d95](https://github.com/vllm-project/vllm-ascend/commit/8fe122d95fc8cc94f32525f9ed36c2b5e3fbfdcc), [vllm_ascend/spec_decode/dspark_proposer.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/spec_decode/dspark_proposer.py), [vllm_ascend/worker/v2/spec_decode/dspark/speculator.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/worker/v2/spec_decode/dspark/speculator.py)

- **Projection bottleneck.** `main_proj` became output-sharded `ColumnParallelLinear` with `gather_output=True` before RMSNorm. Check per-rank weight allocation and AllGather cost. The commit author reports 9 ms → 2 ms for the projection on V4 Pro TP8 with max batched tokens 8192 and explicitly leaves decode end-to-end benefit unquantified. Treat that report as a workload-specific hypothesis for a new run. [1f3418a1a](https://github.com/vllm-project/vllm-ascend/commit/1f3418a1a7fbede99f78d95f12b4cff1bd58a805)
- **Repeated small collectives.** The Markov head is kept replicated because it executes serially for each draft position. LMHead TP slices actual B×K sample indices and pads to the current target bucket, then removes communication padding. Profile padded versus useful rows before changing TP solely to reduce weight memory. [beedc8b8d](https://github.com/vllm-project/vllm-ascend/commit/beedc8b8db84d56c72a2d4d6a3c9de85a741f8e5)
- **Low acceptance only with CP/TP.** The draft `attn_sink` loader must load all sink weights under DSA-CP; ordinary TP slices by local heads. Compare the loaded shapes/values before attributing the symptom to speculative budget or sampling. [f69831343](https://github.com/vllm-project/vllm-ascend/commit/f69831343a1850a363f4892b1f5d5cfe8e4a051d)
- **Input preparation overhead.** The copy/expand kernel vectorizes context copy and query expansion as two independent grid-stride ranges, with launch size based on the larger range and capped by vector cores. Query RoPE positions and linear cache positions are computed separately. Retain that distinction for non-contiguous position IDs. [acbd2bb28](https://github.com/vllm-project/vllm-ascend/commit/acbd2bb28de6d5104a538806950687523c20407a)
- **Zero retained context.** Rejected speculative rows can leave no context. The late fix reads the request's original first position and adjusts it so the first new query starts there. Include a first request with zero retained context, later requests and nonempty controls in a kernel regression. [6f9e86a71](https://github.com/vllm-project/vllm-ascend/commit/6f9e86a714ffbc2d5cfd6740bccf3252b7c81d30)
- **Near the drafter's length limit.** The V1 runner checks maximum sequence length plus the exact query width against the effective draft limit. It publishes empty drafts and clears probabilities when skipping. Model-backed DP ranks still execute an aligned dummy, with a complete DSpark query group. PP ranks without a drafter keep their distinct ownership. Test the exact limit and one-past limit, DP1/DP>1 and PP ownership. [d95acdd88](https://github.com/vllm-project/vllm-ascend/commit/d95acdd8884aa8dd142be9f95a479fa910edc147)
- **Short extends and precision.** The DSA split restored the default short-extend decode classification for DSpark correctness. If a new metadata refactor changes batch classification, compare the per-request query lengths and selected prefill/decode path in addition to shapes. [cb1e180dc](https://github.com/vllm-project/vllm-ascend/commit/cb1e180dc3734cc8e1fa89e40da8310cad01be10)

The tagged four-card DSpark helper measures acceptance length from counters; the earlier [PD procedure](dspark-pd.md) provides the role and connector checks. Native correctness needs generated output/quality evidence, and performance requires fixed request shape, load, cache-hit policy and speculative budget. Relevant kernel regressions reside in `tests/e2e/nightly/single_node/ops/singlecard_ops/triton/test_copy_and_expand_dflash_dspark.py`; fit and publication tests reside in `tests/ut/worker/test_model_runner_v1.py`. [tests/e2e/nightly/single_node/ops/singlecard_ops/triton/test_copy_and_expand_dflash_dspark.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/nightly/single_node/ops/singlecard_ops/triton/test_copy_and_expand_dflash_dspark.py), [tests/ut/worker/test_model_runner_v1.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/worker/test_model_runner_v1.py)

## Readset and verification boundary

This reference distills the selected implementation and regression changes above from history reachable at the RC tag and reconciles their surviving contracts with the tag. Commit-title screening includes documentation, translation, CI baseline changes and other models' DSpark integration; those alone establish no V4 optimization mechanism. The retained procedures cover the inspected diff hunks and named consumers. Native NPU execution, comparative quality, service performance and downstream skill efficacy were not run for this extraction. Keep that evidence status when reusing any historical performance report.

See the [pinned source readset](sources.md) for source identity and verification limits.
