# Model performance procedures at v0.27.1rc1

Start from model family, checkpoint revision and quantization metadata, hardware profile, runner V1/V2, attention layout, TP/DP/PP/DCP settings, and the phase that dominates the trace. The tag contains Kimi K3 and GLM 5-series implementations alongside MiniMax-M3. The RC's formal validation table covers MiniMax-M3 and DeepSeek-V4-Flash. Kimi and GLM entries below describe reachable source behavior and test definitions. Hardware execution and performance measurements for this distillation remain unrun.

## Kimi K3

### Reduce KDA projection work while preserving precision and stream dependencies

1. Inspect `uses_kimi_k3_mixed_kda_projection` against the checkpoint quantization description. The gate requires q/k/v to share one non-FLOAT quantization type and g/f_a/b to be FLOAT. Keep the quantization type and `scale_alg` in the profile record. Other packed layouts follow their own validation path. [Tagged quantization gate](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/quantization/configs/modelslim_config.py)
2. In the mixed path, `_KDAFusedBFGLinear` composes `f_b @ f_a` after both weights arrive and repeats composition on either source reload. Its packed output contains beta, F and the output gate. Verify global versus local f_b shards and the TP equality check when changing the loader. Composition uses FP32 intermediates before conversion to the destination dtype. [BFG projection change](https://github.com/vllm-project/vllm-ascend/commit/cc3537bd59ccb1297bc21619624d1cd7d2ac04c3)
3. Read the event sequence in `_run_overlapped_qkv_bfg` before changing overlap. Main-stream DynamicQuant can run alongside the auxiliary BFG GEMM. The main stream waits for `bfg_projection_ready` before QKV GEMM, and auxiliary gate processing waits for `quant_ready`. The final `bfg_ready` joins the entire auxiliary tail before KDA consumption and graph capture. The two Cube GEMMs are serialized. Check the timeline for vector/Cube overlap and event waits rather than assuming two GEMMs overlap. [Tagged projection and stream implementation](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ops/kimi_kda.py)
4. Confirm beta sigmoid is applied once, in FP32, and that the prepared-beta marker reaches the consumer. Preserve checkpoint RMS epsilon and the one-time convolution weight packing. Use `test_fused_bfg_linear_recomposes_f_after_source_reload`, `test_overlapped_qkv_bfg_keeps_two_stage_vector_cube_overlap`, `test_prepare_beta_does_not_repeat_auxiliary_sigmoid` and the split-quant scale tests to distinguish loader, ordering and precision failures. These mocks establish contracts, with native numerics still requiring NPU tests. [KDA regression oracles](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/ops/test_kimi_kda.py)

### Treat padding and compilation as independent optimization dimensions

- For repeated compilation as request token counts change, inspect the residual kernel's `num_tokens` argument. It is a runtime scalar with `do_not_specialize`; H, valid residual-block count B, capacity and launch dimensions remain compile-time parameters. The regression varies token counts 1, 7, 16, 17 and 512, compares against the reference and requires the same compiled kernel object. Its source commit reports hardware validation pending. Record compile count and warm execution separately. [Token-count specialization change](https://github.com/vllm-project/vllm-ascend/commit/9272234d7d7bb41a5a2a58213d0a20540e5f6365) [Residual reference and kernel-reuse test](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/nightly/single_node/ops/singlecard_ops/triton/test_kimi_k3_fusions.py)
- Preserve contiguous Q/K/V at recurrent KDA and clear both pre-normalization and post-normalization padding. The attempted removal in #16046 was reverted in #16445 after reported A3 4P4D output corruption and reduced DSpark acceptance. A zero input multiplied by a sigmoid of a stale NaN gate can still produce NaN. Include mixed speculative/non-speculative rows, dummy DP work and graph replay in a requalification. [Attempted preprocessing optimization](https://github.com/vllm-project/vllm-ascend/commit/3da432751b879aa529f2399d020eaf25e3793e7f) [Accuracy-driven revert](https://github.com/vllm-project/vllm-ascend/commit/67dd255260e531e159c9de0103b70613ed140107)
- For variable-length prefill failures, size Post-WU scratch by padded chunks × heads × chunk size × key dimension when the post-WU work is separate. Packed token counts underallocate full-chunk writes. The added device test includes mixed short sequences and lengths 80/129, checks finite outputs and compares output plus final state to the reference. [Padded-workspace correction](https://github.com/vllm-project/vllm-ascend/commit/1c4b2768bd3c3362387286431bbea70106765eb9) [Padded-workspace device oracle](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/nightly/single_node/ops/singlecard_ops/test_chunk_kda_aclnn.py)

### Check parallelism before attributing speed or acceptance changes

- Sequence-sharded dense MLP inputs must be gathered before TP-sharded weights. Disable the inner output reduction, then reduce-scatter once. Compare live/padding row placement across ranks. The tagged adapter test verifies the gather → MLP → reduce-scatter sequence. [Dense MLP sequence-parallel correction](https://github.com/vllm-project/vllm-ascend/commit/215043676e00696c0c0c2f89984c57ba495ee532) [Model adapter contract tests](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/models/test_kimi_k3_adapter.py)
- With K3 DSpark and DCP, target verification carries N+1 tokens even when anchor sampling makes draft queries N tokens. Keep prompt chunks classified as prefill under DCP and retain per-KV-group block tables, rank/interleave parameters and first-pass CP metadata. Use target classification, slot mappings and draft outputs to localize an acceptance regression. [K3 DSpark/DCP integration](https://github.com/vllm-project/vllm-ascend/commit/9e2ba22f767e6d3deef757c77f6e91f226d37d7c)
- With prefix caching disabled, compare block sizes across target and draft attention specs separately from Mamba specs. Mamba may use max_model_len as its block size; shared page sizes still need to match. Inspect actual group ownership before assuming equal block size across every cache. [K3 cache-group correction](https://github.com/vllm-project/vllm-ascend/commit/05841f71a6c29e6e0d9752a8adacbe681bd0ab78)

The sixteen-card model fixture exercises small generated K3 configurations, including quantized GQA and PD paths. Record the actual model artifacts and workload when extending its result to a production checkpoint. [K3 model test definitions](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/pull_request/sixteen_card/test_kimi_k3.py)

## MiniMax-M3

### Follow the phase-specific index and sparse-attention implementation

| Trigger | Mechanism and applicable path | Check before calling it an improvement |
| --- | --- | --- |
| Long-context decode spends time in index score and TP communication | #13142 gathers index queries, evaluates rank-local block candidates, then gathers scores/indices and merges top-k. It avoids gathering the full index cache. Later #14539 integrates AscendC block-parallel scoring. | Preserve global block offsets, forced initial/local blocks and causal visibility for each speculative token. Compare top-k and final attention output as well as communication bytes. |
| A5 prefill/decode differs from A3 behavior | At this tag, MSA index prefill uses bundled AscendC, including A5 FP8. A5 decode uses its Triton path over the complete replicated index-K cache. Non-A5 pure-decode TP paths can use block-parallel score metadata. | Capture hardware, phase, query width and actual dispatched operator. Applying non-A5 block sharding to the A5 Triton cache layout changes its input contract. |
| Sparse decode remains expensive after index top-k is cheap | #13987 replaces the sparse decode wrapper with AscendC sparse_attention_score and adds FlashDecoding support in its kernel/tiling. | Query-token count must equal request count × decode_query_len. Compare output against the reference at boundary lengths and speculative widths; measure the selected tile and launch overhead. |
| Triton variants or prefill score preparation dominate | #13532 removes a scalar prefill specialization and changes scalar parameter handling; #16122 uses vector-core-oriented query assignment and contiguous score-block stores. | First verify that the live branch invokes this kernel. Current default AscendC prefill dispatch means a historical Triton microbenchmark may describe a dormant branch. |

### Keep quantization, routing and weight ownership visible

1. Follow the [mixed-cache procedure](minimax-cache.md) for the per-layer BF16/FP8 split. MXFP8 checkpoint loading, native FP8 KV storage and sparse index-score dispatch have separate introduction commits. A5 uses paged index-cache scatter and bypasses the BF16 fused preparation branch. Verify dtype/shape at cache writes and the chosen operator. [ModelOpt MXFP8 integration](https://github.com/vllm-project/vllm-ascend/commit/1acbcc36c30717a233c26a032038089533f6e9d8) [Native FP8 MSA/index integration](https://github.com/vllm-project/vllm-ascend/commit/e61a5d7204fe4a0fc329471df8e4c3c90e9bb2f1)
2. For an index mismatch, verify RMS normalization uses index head dimension rather than the combined query width. Then check top-k visibility, bounds and fixed-scale FP8 casting before investigating speed. [Index-head normalization fix](https://github.com/vllm-project/vllm-ascend/commit/77c12740036c29d3905be53f41594c3c65e41894)
3. If experts are imbalanced, inspect M3 EPLB's logical/physical expert counts, redundant experts, rank mapping and loaded weight placement. EPLB support adds model metadata and loaders; a throughput claim still requires measuring load skew, transfer/rebalancing cost and quality in the selected backend. [M3 EPLB integration](https://github.com/vllm-project/vllm-ascend/commit/6588370e7457098bff6f736582667906e65b2326) [EPLB model tests](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/models/minimax_m3/test_minimax_m3_eplb.py)
4. Use the specific UT for the suspected boundary, then a device oracle. `test_tp_speculative_decode_uses_packed_causal_halo`, `test_tp_topk_applies_init_blocks_by_global_block_id` and `test_speculative_topk_masks_future_blocks_before_selection` cover indexing invariants. Device tests compare top-k and sparse attention with references at decode boundaries and long prefill sequences. Preserve the input shapes and oracle tolerance. [MSA contract tests](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/models/minimax_m3/test_msa_m3.py) [Sparse-attention device tests](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/pull_request/one_card/test_minimax_m3_sparse_attn.py)

## GLM 5, 5.1, 5.2 and 5.3

### Carry GLM-5 dimensions and scalar factors into fused operators

For GLM-5 W8A8, preserve the MLA checkpoint's actual q/kv LoRA ranks, non-RoPE/RoPE head dimensions and head count when selecting preprocessing tiling and allocating scratch. The GLM adaptation replaced DeepSeek-sized constants with tensor-derived dimensions throughout the preprocessing pipeline. For a shape-specific failure, inspect those dimensions before modifying launch tiles. [MLA dimension generalization](https://github.com/vllm-project/vllm-ascend/commit/542258ac9d9229aab4e8822de42443245a93f001)

For an unfused routed-expert residual, compare the FX pattern's scalar to `hf_text_config.routed_scaling_factor`. The GLM fix registers the actual model scalar; a fixed scale of 1 failed to match this graph. Confirm matched_count and output equivalence before attributing fewer launches to a speedup. [GLM muls-add matching fix](https://github.com/vllm-project/vllm-ascend/commit/640ecd1b772b1c3dcdc57336b762cc02d011eba8)

The early SFA refactor separates preprocessing, index selection and attention/parallel handling, while C8 adds quantized indexer storage and scales. Follow the full restoration chain before reusing an old patch. Initial W8A8C8 support was reverted, then restored with registration of the patched MLA spec in the scheduler's manager map. A startup cache-spec lookup failure requires checking initialization and class identity before measuring quantized-cache memory savings. The tagged SFA implementation resolves packed sparse KV and indexer C8 policy separately; retain both effective values in a GLM configuration record. [SFA restructuring](https://github.com/vllm-project/vllm-ascend/commit/2bd9c357886f04eca1ce5f9a00fe09aa77570479), [Initial W8A8C8 change](https://github.com/vllm-project/vllm-ascend/commit/7ed9e9de69160daa66ab61400358da0ecf85107a), [Revert](https://github.com/vllm-project/vllm-ascend/commit/0c299f79b92af96b36518b6497d4817a84aeb49e), [Restoration and manager registration](https://github.com/vllm-project/vllm-ascend/commit/4d443b922811e1094fba660a8faed0d493541571).

### Reduce repeated index work only where the checkpoint supplies the dependency

1. Distinguish runtime IndexCache from checkpoint IndexShare. GLM-5.1 can skip top-k calculation while retaining an indexer tensor in every layer. GLM-5.2 can mark a backbone layer as `shared` and omit that indexer. The patch keeps MTP/nextn indexers available. Deleting a GLM-5.1 indexer because `skip_topk` is true breaks weight loading. [GLM-5.1 versus 5.2 indexer correction](https://github.com/vllm-project/vllm-ascend/commit/929e461de828de233c2047def41a26a02c768084) [Tagged indexer construction](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/patch/worker/patch_deepseek_v2.py)
2. Inspect the target buffer and every consuming layer. `skip_topk` reads the cached top-k rows; recomputing layers publish rows back to the buffer when caching is active. Each SFA layer still records KV-written and attention-start events so layerwise transfer and prefetch can progress even when the indexer is absent. Trace a stalled PD/offload pipeline at these events. [SFA cache producer and consumer](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/attention/sfa_v1.py)
3. Check PP boundaries against both `indexer_types` and top-k recomputation pattern/frequency. Each stage must have its own preceding full indexer or top-k producer. The platform rejects a stage starting at a skipped top-k layer and shared indexers whose producer lies on another stage. Adjust a partition according to the actual checkpoint layout before benchmarking PP. [IndexShare/IndexCache PP validation](https://github.com/vllm-project/vllm-ascend/commit/12276de8059151c56c876154abc536b92d8681e4) [Aligned and rejected PP fixtures](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/test_platform.py)
4. For MTP reuse, read `index_share_for_mtp_iteration` from the draft configuration. The proposer shares the target's buffer into draft consumers, recomputes at the first draft step and skips subsequent top-k work. Confirm buffer lifetime and step-zero publication before measuring saved indexer time. The original unit test includes a simulated control-flow test, so use the actual proposer path plus device generation for stronger verification. [MTP top-k reuse](https://github.com/vllm-project/vllm-ascend/commit/463a6a1d065d246918e4cb4319e07ae63a2d2c9e) [Tagged sharing and iteration logic](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/spec_decode/llm_base_proposer.py)

### Recover GLM-5.2 DSpark acceptance before tuning draft length

For a QuaRot target, auxiliary hidden states arrive in rotated space. `process_weight` rotates each fc input-width chunk with the global rotation matrix. Runner V2 applies target rotation after loading the draft because upstream loading can replace the draft quant config with None. Confirm target rotation identity, fc shape and a single correctly placed transform. The anchor flag and draft attention causality must also come from the checkpoint/model API. V1 and V2 loading paths therefore need separate checks. Their acceptance-length helper checks counters and a relative tolerance. Run a separate fixed-prompt correctness check and matched-load benchmark to qualify quality and latency. [Rotation UT](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/spec_decode/test_dspark_speculator.py) [Runner V1 acceptance fixtures](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/pull_request/eight_card/test_glm5_2.py) [Runner V2 acceptance fixtures](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/pull_request/eight_card/model_runner_v2/test_glm5_2.py)

### Evaluate GLM-5.3 native FP8 by the weight consumer

- Partial TP/merged shards need a block-scale parameter that rounds scale tiles up at the tail. Reusing bit-packing integer division can drop a required scale tile. The loader also flattens paired dynamic-MX scale axes before the consuming scheme repacks them. Inspect weight/scale shards before attributing an issue to FP8 arithmetic.
- The scheme can requantize to MXFP8 on 950; reduction dimensions that fail the MX grouping constraint use the dense fallback. `kv_b_proj` is retained dense for SFA absorption into W_UK/W_UV because the original projection will be disposed. Verify actual dispatched method and absorbed-weight dtype when interpreting memory or GEMM savings.
- When the checkpoint has no MTP head, explicit head ownership selects the target head. Comparing uninitialized draft weights can otherwise retain garbage and destroy acceptance. Test missing-head, owned-head and equal-head cases independently.

These behaviors are introduced together in the native FP8 change. Its reported benchmark uses random-token input with ignore-eos and admits queueing-dominated TTFT; the commit also states the absence of a measured GLM-5.3 accuracy baseline. Record workload and quality evidence before using those numbers as a serving expectation. [GLM-5.3 FP8 support and reported limits](https://github.com/vllm-project/vllm-ascend/commit/c2806729033d98c53c2a782fefa424791e466c5f) [FP8 shape, regroup and fallback tests](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/quantization/methods/test_fp8_block.py) [MTP head ownership tests](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/spec_decode/test_llm_base_proposer.py)

For DSA-CP, FlashComm1 and fused-MC2 interactions, use the [communication/configuration procedure](communication-config.md) after identifying the model-specific path above. Return the effective dispatch, first failed invariant, source commit and matched comparison workload. All native speed, numerical quality and skill efficacy claims remain to be evaluated in the actual environment.
