# Select a fusion by its effective dispatch and oracle

Use the full-history [inventory](history-inventory.json) to find candidate changes, then reconcile their implementation with this tag. A historical speedup and an eligible present-day graph are separate evidence. The decision records below preserve removals, shape gates and counterexamples.

## Graph norm/quant, QK normalization and residual fusion

1. Inspect the validated `ascend_compilation_config` and the actual compile backend. The three graph-manager switches default true at this pin. Norm-quant and muls-add are skipped on 310P. A requested switch still needs a registered pattern and a match in the captured graph. Record `matched_count`, compiled versus eager graph and the operator trace.
2. Norm-quant accepts BF16/FP16 model dtypes. The int4 schemes W4A4_DYNAMIC and W4A4_FLATQUANT_DYNAMIC disable its registrations. Registered epsilon choices are 1e-5 and 1e-6. Static and bias patterns require custom operators; dynamic MX patterns are A5-only. Check residual output, quant scale and bias semantics as well as quantized output.
3. A concrete historical miss occurred because the pattern expected `npu_add_rms_norm`, while the model graph emitted `_C_ascend.npu_add_rms_norm_bias` with a None bias. Both graph backends needed alignment. When fusion disappears after a model/runtime update, compare emitted call targets before changing numerical parameters. [pattern correction](https://github.com/vllm-project/vllm-ascend/commit/56269eae0e553909ab8dad60deb5c9235988a04e) and [npugraph_ex correction](https://github.com/vllm-project/vllm-ascend/commit/87a0b7b7c7630ae112c8384ad1af11ed29d55801).
4. QK/RoPE registers BF16 with discovered Attention layers and head size 128. The pattern uses the discovered head counts and the supported epsilon variants. Muls-add permits FP16/BF16/FP32 and reads `routed_scaling_factor` from model config. Its historical constant 1.0 missed GLM5's 2.5 pattern. Preserve the model value. [GLM5 scalar correction](https://github.com/vllm-project/vllm-ascend/commit/640ecd1b772b1c3dcdc57336b762cc02d011eba8).
5. Compare eager and compiled numerics with the tagged one-card norm-quant and QK/RoPE tests before benchmarking. Test both bias variants, actual scale shape and graph shape. The MX fusion commit reports operator timing on an earlier CANN/PTA build; establish a fresh baseline for this RC. [A5 dynamic MX fusion](https://github.com/vllm-project/vllm-ascend/commit/bb2666df29c4cddab74fd340103f18bd5bf2bb9f).

Source consumers and test entry points are [vllm_ascend/compilation/graph_fusion_pass_manager.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/compilation/graph_fusion_pass_manager.py), [vllm_ascend/compilation/passes/norm_quant_fusion_pass.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/compilation/passes/norm_quant_fusion_pass.py), [vllm_ascend/compilation/passes/qknorm_rope_fusion_pass.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/compilation/passes/qknorm_rope_fusion_pass.py), [vllm_ascend/compilation/passes/muls_add_pass.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/compilation/passes/muls_add_pass.py) and [tests/e2e/pull_request/one_card/compile/test_norm_quant_fusion.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/pull_request/one_card/compile/test_norm_quant_fusion.py).

## Grouped GEMM, activation and requantization

The useful fused unit is gate/up grouped matmul → activation → dynamic quantization, followed by the down projection. It reduces intermediate traffic and launches, but activation and scale layout determine eligibility.

- The original W8A8_DYNAMIC GMM/SwiGLU/quant work reports gains for a specific Qwen3 workload and parallel layout. Current `quant_apply_mlp` first distinguishes ordinary SwiGLU, SiTU, GELU, SwiGLUStep and the MiniMax-M3 un-interleaved OAI form. Preserve clipping, alpha/beta and activation ordering when comparing paths. [original grouped fusion](https://github.com/vllm-project/vllm-ascend/commit/aff5189c8781f1127d7dbca6c59a9ec44a427100).
- For SiTU, the RC gate requires A5, MXFP enabled, W4A8MXFP, SiTU activation, group-list type 0 or 1 and absence of the per-channel path. The gate selects fusion automatically. The A5 adaptor restores semantic FP4 weights and E8M0 scales from suitable ND uint8 views, selects Tensor or TensorList overload, and aligns transposed scales. Its scale-alignment check can raise on unsupported strides. Capture dtype, physical format, strides and group-list meaning before introducing copies. [GMM-SiTU integration](https://github.com/vllm-project/vllm-ascend/commit/7ba437c5f6fdb08fc71bd4bb9864eb654cabedfd).
- The shared GMM/SwiGLU gate excludes SiTU and un-interleaved OAI. Dynamic EPLB plus fusion takes a different custom-op branch from the ordinary fused path. A MiniMax-M3 checkpoint cannot be reinterpreted as SiTU solely because both have gate/up weights. Check the actual activation enum at the call site.
- Validate fused and unfused activation/output scales with the matching test fixtures, then run model quality and measured service load. For Kimi SiTU use the tagged `test_kimi_k3_situ_fusion_cases.py` on its required device. A passing shape or Meta-dispatch test only checks that contract.

Inspect [vllm_ascend/ops/fused_moe/moe_mlp.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ops/fused_moe/moe_mlp.py), [vllm_ascend/device/device_op.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/device/device_op.py) and [tests/e2e/nightly/single_node/ops/singlecard_ops/test_kimi_k3_situ_fusion_cases.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/nightly/single_node/ops/singlecard_ops/test_kimi_k3_situ_fusion_cases.py).

## Fuse communication only after checking tensor ownership

SFA DCP post-processing formerly exchanged partial output and LSE separately. The fused path packs both, performs one HCCL all-to-all and combines rank contributions using stable LSE weighting. BF16/FP16 payloads encode the FP32 LSE as four exactly representable integer fields, preserving finite values outside FP16's range. Invalid contributions receive zero weight; an all-invalid row returns zero. Verify both scatter dimensions, divisibility, positive strides, actual DCP group and non-contiguous input. Shape-only FakeTensor dispatch executes no collective. [one-collective SFA DCP fusion](https://github.com/vllm-project/vllm-ascend/commit/5c59cfba98045f49645284745be035346a4d82d8).

Run the single-card packing/reduction tests and the two-rank HCCL test separately, preserving valid extreme LSE and all-invalid cases. Benchmark at the same tokens, heads, head dimension and rank count. Use [vllm_ascend/ops/triton/docs/sfa_cp_a2a_fused.md](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ops/triton/docs/sfa_cp_a2a_fused.md) and [tests/e2e/nightly/single_node/ops/multicard_ops_a3/test_sfa_cp_a2a.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/nightly/single_node/ops/multicard_ops_a3/test_sfa_cp_a2a.py).

The original fused matmul/reduce-scatter caller in SequenceRowParallelOp was removed by the FlashComm cleanup. This tag retains adaptor wrappers, while a runtime-tree search finds no call to DeviceOperator.npu_mm_reduce_scatter_base. Treat that introduction as historical. MoE dispatch/FFN/combine retains its separate live dispatch gates. Consult [communication configuration](communication-config.md) before enabling the latter. Historical DispatchFFNCombine optimization packs tokens with scales and communicates combine tiles earlier. Its original environment-variable launch example predates this RC's config migration. [DispatchFFNCombine changes](https://github.com/vllm-project/vllm-ascend/commit/832552836842e00cc9de75bc853a90338694ccc4) and [matmul/reduce-scatter introduction](https://github.com/vllm-project/vllm-ascend/commit/0b1da2474260bd30c5a70f8090c2e6d14ee5d684).

## Fused MLA/SFA preprocessing and KV writes

MLA prolog v3 combines projection, normalization, RoPE and cache work under a dtype/layout contract. The unification change consolidates MLA callers onto v3 and reorganizes weight and quant-scale preparation. At the tag, inspect FP8-attention capability, weight quant mode, whether RoPE is enabled, PA_BSND versus PA_NZ cache mode and decode token count. A no-RoPE branch selects its own wrapper. Compare the transformed projection weights and scales to the actual kernel operands before evaluating copy savings. [Unification change](https://github.com/vllm-project/vllm-ascend/commit/128ecf890fc36f29492f7232214e8d63d2e3c28e) and [current MLA consumer](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/attention/mla_v1.py).

Under DCP, SFA cache writes and lightning-indexer cache writes have distinct slot mappings. The v3 correction threads the DCP-sharded SFA mapping into fused preprocessing and the LI mapping into its scatter writes. A fast fused kernel writing through the wrong mapping silently breaks cache ownership. Validate both cache tensors after a fixed batch, including uneven shards. [Slot-mapping correction](https://github.com/vllm-project/vllm-ascend/commit/657df3efae6479822970081636ffb9684f936d2f) and [SFA consumer](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/attention/sfa_v1.py).

Direct TP QKV/RMS/RoPE kernels also have their own launch and caller constraints. Their grid-stride/H-loading optimization belongs to a distinct direct-op route, whose applicability must be checked independently from graph-pattern registration. [Direct-op optimization](https://github.com/vllm-project/vllm-ascend/commit/344931832c3f7fb14ce7fe3f8d5c9d8a7b61e2fa).

For the direct TP route, inspect the actual [MiniMax-M2 patch caller](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/patch/worker/patch_minimax_m2.py) and use its [TP fused-op numerical test](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/nightly/single_node/ops/singlecard_ops/triton/test_split_qkv_tp_rmsnorm_rope.py) with the same split, head and rotary dimensions.

## Operator availability and framework integration

For GDN prefill, the tagged implementation probes `npu_chunk_gated_delta_rule` with a small native call, caches availability per process, and requires PCP world size 1 for the fused branch. It falls back to the Triton pipeline when the interface or probe fails. Check the effective probe result and process lifetime after changing CANN packages. The introduction's description of an optional/default path is historical; inspect the current caller. [fused GDN introduction](https://github.com/vllm-project/vllm-ascend/commit/77d13e2c0bfa9862b711b68811889e36b9d56aca) and [vllm_ascend/ops/gdn.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ops/gdn.py).

GDN gating has a separate rollback history. The AscendC gating implementation, bindings and build sources were removed, and the device adaptor now calls `fused_gdn_gating_patch` in Triton. A native chunk-prefill probe result says nothing about which gating implementation is selected. [Gating rollback](https://github.com/vllm-project/vllm-ascend/commit/c794923e62b4050b8e812ec8f0d0b635088e064d) and [current device adaptor](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/device/device_op.py).

The sparse-attention-overlap addition supplies an AscendC operator intended to hide host-to-device misses with attention on resident top-k KV. Its introduction explicitly defers framework integration. At this tag, a search of `vllm_ascend/` finds no call to `fused_sparse_attention_overlap`. Use its nightly operator test to inspect operator capability; require a real runtime caller and transfer trace before expecting serving acceleration. [sparse offload operator introduction](https://github.com/vllm-project/vllm-ascend/commit/d1523852b416be34cfea126a9134bb3519771834) and [tests/e2e/nightly/single_node/ops/singlecard_ops/test_fused_sparse_attention_overlap.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/nightly/single_node/ops/singlecard_ops/test_fused_sparse_attention_overlap.py).

## Preserve counterexamples to “fewer operators is faster”

| Historical path | What changed | Decision at this tag |
| --- | --- | --- |
| Fused top-k/top-p | Early fused-op adoption was followed by a removal motivated by host synchronization and accuracy risk, and later by a sort-based non-reduce path for large or mixed k. | Inspect reduce-sample mode and k distribution. The non-reduce caller now selects sort-based masking; the fused op still appears in a reduced-value path. |
| Matmul-allreduce-add-RMSNorm | Dedicated env, operator, graph pass and tests were removed. | Use the current manager's supported passes. Historical allreduce-RMS examples cannot enable this deleted path. |
| Kimi preprocessing-copy removal | RC later reverted it after accuracy problems. | Preserve restored copy/layout behavior and investigate performance within valid output semantics. See [model performance](model-performance.md). |

The sampling sequence is [initial fused sampling](https://github.com/vllm-project/vllm-ascend/commit/2fda60464c287fe456b4a2f27e63996edc65dd40), [synchronization-driven removal](https://github.com/vllm-project/vllm-ascend/commit/515267de22dd499a768fdcadae79f45e4a58ba49) and [sort-based non-reduce selection](https://github.com/vllm-project/vllm-ascend/commit/994765d7ab3ac2661865d149c803146927366b26). The deletion of the matmul-allreduce path is [removal commit](https://github.com/vllm-project/vllm-ascend/commit/2ee50f3847e4873e61d280911b2a24d85f5278d6). The current sampling caller is [vllm_ascend/sample/sampler.py](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/sample/sampler.py).

For every proposed fusion report the selected branch, numerical reference, workload shape, launch/transfer count and measured latency separately. All performance numbers in historical commits are upstream reports. This extraction performs source analysis and host packaging checks; NPU numerical, throughput and efficacy validation remains outstanding.
