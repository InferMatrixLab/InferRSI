# Resolve DSA-CP, FlashComm and fused MoE communication

Use this procedure when a copied launch command changes throughput, leaves DSA-CP disabled, selects an unexpected MoE operator, or fails during prefill. Freeze the target checkpoint, draft checkpoint, runner, plugin revision, upstream vLLM revision, hardware profile, P/D role, TP/DP/EP/PCP sizes, token shape and installed operator packages. The source contract below is `v0.27.1rc1` at `3b31886237ed65c435e0965b10e8002ff5769766`. Each rank needs both requested inputs and the derived configuration.

## Recover the effective settings

1. Read configuration through `init_ascend_config(vllm_config)`. The factory validates typed inputs, applies cross-field derivations and only then publishes the singleton and clears cached utility predicates. Constructing the dataclass alone leaves this sequence incomplete. The same `vllm_config` object can reuse the cached result, so collect evidence from a fresh initialization when comparing configurations. `enable_dsa_cp()` reads the resolved singleton, while `enable_sp(vc)` reads `parallel_config.use_sequence_parallel_moe`. [Factory and publication](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L1399), [SP reader](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/utils.py#L811), [DSA-CP reader](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/utils.py#L1330).
2. Remove the obsolete `VLLM_ASCEND_ENABLE_FUSED_MC2` export from the proposed launch and express the desired value in `additional_config.enable_fused_mc2`. Its default is 0. Commit #14831 removes the environment reader and its fallback mapping. The tagged DeepSeek-V4-Flash tutorial still contains that export and a parameter description, so a tutorial-derived environment alone leaves fused MC2 at its default. Record this source disagreement when diagnosing an apparently enabled path. [Removal diff](https://github.com/vllm-project/vllm-ascend/commit/80c833fb86b105391d164c9e3fc60d0bfecbf85e), [current defaults](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L384), [stale tutorial description](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/docs/source/tutorials/models/DeepSeek-V4-Flash.md#L1303).
3. Preserve any legacy FlashComm input in the diagnosis. `init_ascend_config` warns about both `enable_flashcomm1` and `VLLM_ASCEND_ENABLE_FLASHCOMM1` and strips the additional-config key before strict dataclass construction. Later derivation still reads the original key and ORs it with environment values `1` or `true`, then ORs that result with requested DSA-CP. A false JSON value cannot override a true environment value in this expression. This version therefore requires inspection of both inputs despite the deprecation warning. [Warning and filtering](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L1401), [effective expression](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L519).

| Requested configuration and prerequisites | Derived behavior to inspect |
| --- | --- |
| Both legacy FlashComm inputs false/absent, DSA-CP false | If SP is initially true, derivation changes `all2all_backend` to `flashinfer_all2allv`, disabling SP. |
| DSA-CP true, EP enabled, TP > 1, SP-capable backend and `hf_text_config.index_topk` present | The existing SP-capable backend is retained and effective DSA-CP stays enabled. A separate FlashComm request is unnecessary. |
| DSA-CP true, TP = 1, EP disabled or non-SP backend | Effective DSA-CP becomes false. The auto-enable message alone cannot establish the final value. |
| DSA-CP true, SP available, indexer attribute absent | Effective DSA-CP becomes false after the model gate. Inspect SP independently because the earlier backend decision already used the requested DSA-CP value. |
| FlashComm true, DSA-CP false, EP enabled and TP > 1 | Eligible SP remains enabled. `enable_shared_expert_dp` has its own EP/TP gate and its own default. |

The derivation only forces an ineligible SP backend off. It does not replace an explicitly non-SP backend with an eligible one. The patched SP property admits `allgather_reducescatter`, `deepep_high_throughput`, `deepep_low_latency`, `mori_high_throughput`, `mori_low_latency` and `nixl_ep`, with EP enabled and TP > 1. DP = 1 is supported by this patch. Retain that distinction when reading older test comments mentioning DP > 1. [Normalization and model gate](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L509), [patched property](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/patch/platform/patch_parallel_config.py#L19), [DP=1 regression cases](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/patch/platform/test_patch_parallel_config.py#L22).

## Follow the DSA-CP computation and communication

For DeepSeek V4, inspect token ownership at the model boundary, decoder attention, MoE input and final output. Model-level SP shards hidden states and input IDs once, maintains padding information and gathers the final hidden states before the head. The decoder passes `need_gather_q_kv` when SP and DSA-CP are both active. The DSA-CP attention consumer gathers full hidden states for KV updates while Q computation consumes the local token shard. The output path uses reduce-scatter where needed and has a separate full gathered o-projection-weight path. A collective count without these tensor layouts can conceal a duplicate gather or a wrong residual shape. [Model boundary](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/models/deepseek_v4/model.py#L892), [decoder contract](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/models/deepseek_v4/model.py#L674), [attention consumer](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/attention/context_parallel/dsa_cp.py#L1511), [padding and collectives](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/models/common/ops/sequence_parallel.py#L22).

The performance hypothesis is reduced replicated work and fewer full-token-layout transitions between layers, balanced against the KV gather and output collectives. Inspect prefill and decode separately. Commit #16021 moved sharding from the MoE body to the model and revised attention collectives after the FlashComm removal. Its author reported median TTFT 2796 ms and TPOT 43.75 ms versus 3105 ms and 45.57 ms for the compared main branch, with DeepSeek-V4-Flash W8A8, DP2/TP4/EP, random 8192-input/2048-output requests, 50 prompts and concurrency 8. Those are historical commit-message results with their own upstream revision and hardware evidence limits. Reproduce the selected workload on the intended stack before assigning a benefit to this RC. [Change and author report](https://github.com/vllm-project/vllm-ascend/commit/78bf96a55bc91466eae7ac5fe080596fac7b9d5a).

For a load-dependent QLI metadata hang, inspect the device-local `query_start_loc` used by the metadata consumer. The RC restores a device-derived query maximum on a QLI metadata cache miss after asynchronous host metadata could diverge. Preserve this ordering and record cache-hit/miss behavior before attempting to remove its `.item()` synchronization. The upstream fix reported focused CPU and NPU UTs while high-concurrency NPU validation remained pending in its message. [QLI correction](https://github.com/vllm-project/vllm-ascend/commit/93b7942540c53d8d4486c2cc4579f356f520d0e0), [current consumer](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/attention/context_parallel/dsa_cp.py#L1140).

DSA-CP also emits a future-deprecation warning. PCP is experimental in this tag. The suggested TP=N to TP=1/PCP=N migration preserves rank count, but requires checking model and feature support and removing `enable_dsa_cp` when trying PCP. With TP=1, increasing PCP adds ranks. Capture the original and candidate parallel layouts explicitly. [Migration conditions](https://github.com/vllm-project/vllm-ascend/commit/2295ef002de030df621a276317648925114aef03).

## Resolve fused-MC2 dispatch before benchmarking it

1. Read the normalized `enable_fused_mc2` and `is_mega_moe_supported()` together. Values 0 and 1 force the MegaMoe availability state false in the range validator. Ordinary value 1 selects the legacy `dispatch_ffn_combine` fused path when hardware and EP dispatch permit it. Value 2 is retained for testing MegaMoe, probes `cann_ops_transformer`, then normalizes the field to 1. Its subsequent model gate can disable fused MC2. Avoid inferring the selected operator from the final integer alone. [Current normalization](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L455), [runtime accessor](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L33).
2. Apply the configuration conflicts first. MiniMax-M3 architectures reject fused MC2 = 1. A fused request disables `multistream_overlap_shared_expert`. Hierarchy communication rejects fused MC2. MoE LoRA also rejects a nonzero fused setting because its implementation cannot patch the single fused operation. `enable_shared_expert_dp` is a separate replication control and must be recorded separately from multistream overlap. [Model and overlap gates](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L617), [hierarchy gate](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L740), [LoRA gate](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/lora/fused_moe.py#L166).
3. Inspect `select_moe_comm_method` for the actual device and batch. A3 with EP > 1 selects fused MC2 for the normal fused path at EP <= 32. A3's experimental MegaMoe path additionally requires its availability, MoE, EP <= 64 and no LoRA. Larger A3 EP falls back to MC2 within capacity or all-to-all above capacity. A5 uses its MC2/all-gather/all-to-all decision and has no FUSED_MC2 return in that branch. EP disabled or EP=1 yields all-gather. Record the selected enum and operator trace for the target batch. [Hardware dispatch](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_forward_context.py#L299), [MegaMoe predicate](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_forward_context.py#L84).
4. At `FusedMC2CommImpl.fused_experts`, distinguish `_apply_cann_mega_moe` from `torch.ops._C_ascend.dispatch_ffn_combine`. The legacy call consumes expert IDs, routing probabilities, weight scales, scale biases, communication group and active mask in one operation. Missing `w1_scale_bias` or `w2_scale_bias` triggers an assertion on this path. Thus a dispatch unit test does not establish that a particular checkpoint's weight preparation meets the operator contract. [Operator arguments and result](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ops/fused_moe/moe_comm_method.py#L448).
5. Inspect per-rank receive capacity and HBM. `mega_moe_max_tokens` defaults to 65536 and is passed as the legacy fused operator's `max_output_size`; MegaMoe uses it for symmetric receive-buffer allocation. The source warns that exceeding it can truncate tokens and harm precision, while workspace grows with capacity. Keep this receive-token capacity distinct from scheduler tokens and graph capture tiers. `enable_prefill_mc2` separately affects the MC2 token-capacity calculation. [Capacity field](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L396), [runtime capacity calculation](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_forward_context.py#L232).

Fusing expert dispatch, FFN and combination changes launch overhead and communication/computation overlap. It also replaces the shared-expert-overlap configuration when that option was requested. Compare resolved configurations and measured traces before attributing an improvement to fusion. Source routing alone supplies no speedup result.

For the separate regular-MC2 algorithm control, `mc2_comm_alg` accepts the empty default, `fullmesh`, `hierarchy` or `fullmesh_v2`. A3 maps `fullmesh` to the operator spelling `fullmesh_v1`. Hierarchy requires its hardware capability, at most 512 logical-plus-redundant experts and fused MC2 disabled. It forces DP token all-reduce/padding because dynamic `global_bs` is unsupported there. Check the resolved communication algorithm and collective trace when comparing latency. [Algorithm normalization](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ascend_config.py#L935), [dispatch arguments](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/ops/fused_moe/token_dispatcher.py#L112), [DP synchronization condition](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/vllm_ascend/utils.py#L1112).

## Select a check for the suspected boundary

| Suspected failure | Tagged check and expected discriminator |
| --- | --- |
| DSA-CP request becomes false, or removing FlashComm changes layout | `tests/ut/test_ascend_config.py` cases `test_dsa_cp_enabled_auto_keeps_sp_when_conditions_met`, `test_dsa_cp_enabled_auto_disabled_when_sp_conditions_not_met`, `test_flashcomm_disabled_forces_sp_off_when_conditions_met` and `test_enable_dsa_cp_model_gate_is_resolved_during_init`. Inspect derived booleans and backend, including the typed string `false` case. |
| DP=1 unexpectedly disables SP | `tests/ut/patch/platform/test_patch_parallel_config.py` tests DP=1/DP>1 and rejects TP1, EP-disabled and non-SP backend cases. |
| Wrong A3/A5 communication method or ineffective MegaMoe rollback | `tests/ut/test_ascend_forward_context.py` cases `test_select_moe_comm_method_a3_enable_fused_mc2_mode_1` and `test_select_moe_comm_method_a5`; `tests/ut/test_ascend_config.py::TestTopLevelSwitchTypeValidation::test_fused_mc2_rolls_back_even_when_config_supported`. |
| DSA-CP changes prefill/decode outputs | `tests/e2e/pull_request/four_card/context_parallel/test_accuracy.py::test_deepseek_v4_dsa_cp_prefill_decode_accuracy` compares on/off greedy output tokens for prompt lengths 1, 3, 4095, 4096 and 4097 using DP2/TP2/EP, eager execution and the declared test checkpoint. Its coverage metadata names A3. Preserve that fixture scope. |
| QLI metadata hangs under asynchronous scheduling | `tests/ut/attention/test_dsa_v1.py::test_dsa_cp_qli_metadata_uses_device_query_lengths`, followed by an authorized concurrent device workload if the regression needs runtime qualification. |

The tests above were inspected as executable oracles. This distillation did not run the NPU suite or establish a serving gain. For an A/B run, freeze checkpoint, hardware, parallel layout, input/output lengths, prefix-hit rate, graph mode, warmup and load. Retain correctness, TTFT, TPOT, throughput, per-rank peak HBM and operator/collective traces together. Report configuration normalization before comparing either latency or memory. [Configuration tests](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/test_ascend_config.py#L1025), [dispatch tests](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/test_ascend_forward_context.py#L304), [device accuracy oracle](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/e2e/pull_request/four_card/context_parallel/test_accuracy.py#L201), [QLI regression](https://github.com/vllm-project/vllm-ascend/blob/3b31886237ed65c435e0965b10e8002ff5769766/tests/ut/attention/test_dsa_v1.py#L500).
