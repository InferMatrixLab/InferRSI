## Version and hardware constraints

F: [Pinned constraint section L237-L268](https://github.com/Ascend/pytorch/blob/67511c53cd4c88014f6123de7097677e60e85faa/docs/zh/api/environment_variable/memory_management/PYTORCH_NPU_ALLOC_CONF.md#L237-L268) specifies:

- Device expandable segments: HDK 23.0.0+; single-process multi-device behavior has an additional HDK 24.1.RC3/TorchNPU 6.0.RC3 boundary ([multi-device note L127-L129](https://github.com/Ascend/pytorch/blob/67511c53cd4c88014f6123de7097677e60e85faa/docs/zh/api/environment_variable/memory_management/PYTORCH_NPU_ALLOC_CONF.md#L127-L129)).
- 1 GiB page option: HDK 25.0.RC1+, commercial CANN 8.1.RC1+, specifically listed Atlas A2/A3 training products. This is a feature gate, not a universal TorchNPU minimum.
- Lazy multi-stream reclaim: TorchNPU newer than 7.3.0 per the pinned Chinese wording; benefit is targeted at host-side submission overhead.
- Newer options and PYTORCH_ALLOC_CONF alias have their own TorchNPU/PyTorch gates. Do not extrapolate their availability from this source snapshot.
- [950DT restriction L13-L16](https://github.com/Ascend/pytorch/blob/67511c53cd4c88014f6123de7097677e60e85faa/docs/zh/api/environment_variable/memory_management/PYTORCH_NPU_ALLOC_CONF.md#L13-L16) lists only four supported options for Ascend 950DT; verify the exact product rather than broadening support from a generic Ascend label.

## Proposed verification and limits

P: Given later authorization and a matched NPU stack, use a bounded producer/consumer test with explicit data dependency, early Python-reference release, pending side-stream work and allocation pressure. Check no premature storage reuse and correct output; then compare the same sequence's peak/resident statistics, retry counts and latency with one knob changed. Record synchronization boundaries so synchronization itself is not mistaken for an allocator win.

P: Capacity dominated by live tensors, capture-private retention, custom allocators and external IPC ownership are different investigations. This bundle does not establish graph-pool destruction rules, IPC interoperability, HCCL transport, device-driver behavior or a compatible base-PyTorch revision. Source test existence is not passing evidence.

## Resource scope

Accelerator / device HBM: lifetime and fragmentation diagnosis, version-gated configuration hypotheses and proposed verification. Device event/lifetime evidence supplies no RAM/Host, SSD or Network coverage. The two TorchNPU studies are one upstream source, not independent corroboration.
