# Ascend native offload: CPU descriptor ownership

## Scope and evidence

This source-derived candidate covers the normal descriptor-pool path in vllm-project/vllm-ascend at `8a8e1e05ecb64a30804c99c8f362909f9a0cb5bf`, tree `5ca8fb3b2c6b9a64d74a3b9a74403ce44014e4a5`. Use the [seven-file ledger](vllm-ascend-native-offload-readset.json) for exact bytes, line bounds and source identities. `F` denotes observed source; `P` denotes a proposed diagnosis or check. Status remains candidate; empirical validation is not_run.

Use this case when the native single CPU-tier offload worker retains host memory after a transfer submission or tracked-job wait, or a proposed change would reuse its CPU pointer/size arrays earlier. These arrays describe copies; they are different from the CPU KV payload mirrors. The case does not establish TorchNPU allocator behavior, physical RAM return, model correctness or a performance improvement.

The selected path is `NPUOffloadingSpec` creating `NPUOffloadingWorker` without a shared region. Tiering/shared mmap, the separate simple/preempt offload implementations, inherited prefetch ownership, ACLGraph and upstream request eviction are outside this case. A compatible vLLM revision and its manager, `compute_sub_block_ptrs` and ABI remain unpinned. The declared Torch/TorchNPU versions in the ledger are not a tested compatibility set.

## Bounded procedure (P)

1. **Confirm the path and objects.** Obtain the installed source/version, actual native single-tier worker/spec, transfer direction and real job/event state. Separate CPU payload mirrors, per-job descriptor arrays, pooled descriptors and allocator-owned cached memory. If a different implementation or shared region is selected, this case is insufficient.
2. **Preserve normal ownership.** Use F2–F4 to trace a descriptor triple from allocation/pop through the C++ consumer and queued Transfer to successful head-event query. A submission returning True or an event being recorded does not establish completion. Do not move the normal pool return earlier on that evidence.
3. **Separate readiness from reclamation.** For a tracked event, wait can synchronize without removing the Transfer or reclaiming its descriptors. A later normal poll performs those ownership transitions. Inspect that state before labeling retained descriptor RAM a leak. Pooling intentionally keeps storage available for reuse; reference clearing does not establish physical page return to the OS.
4. **Respect ordering and allocation boundaries.** Preserve D2H's model-stream dependency and per-direction transfer ordering. A reclaimed triple that is too small is replaced in the source. Conditional pinning, CPU dispatch or an async API name alone does not establish overlap, correctness or speed.
5. **Report cleanup exactly.** Preserve F5's pop/synchronize/clear order in the diagnosis. Do not extrapolate normal polling ownership into a claim that shutdown retains every descriptor through its wait. Escalate teardown errors or a proposed shutdown change to a separately pinned CANN/TorchNPU/vLLM investigation.
6. **Choose one evidence-matched proposal.** Prefer preserving the queue/pool contract and observing the actual owner state. A later authorized native check should use the real compatible stack, real events and transfers, checking copied bytes and reuse after completion. Record source selection, job/direction, query/wait/pool transitions and host residency separately. No mock events, fake tensors or extracted substitute implementation can qualify the native path.

Return the selected path, F evidence, observed versus missing state, the smallest proposed action, and the remaining validation gap. Stop before an optimization when the installed path/ABI is unknown, ownership is shared, or event/runtime errors prevent completion evidence.
