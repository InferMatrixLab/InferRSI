# 共性排障

| 现象 | 检查 | 恢复 |
|---|---|---|
| `pip install .` 失败或触发意外安装 | 本仓库 setup 是应用引导程序 | 使用明确构建流程或已准备应用环境，调用 setup 前先检查依赖 |
| 参数未生效或解析失败 | 安装器、服务和引擎参数不同，模型族也有差异 | 核对相应 parser 和实际启动命令，保留回退日志 |
| 修改设置后 OOM | KV、MTP、batch 状态、图捕获和 prefill 临时区共享专家缓存预算 | 恢复基线，定位分配，再改变一个内存组件 |
| 低内存模式极慢 | 文件映射专家可能从 SSD 缺页载入，常驻或 pinning 可能失败 | 查看 resident/mapped 模式与缺页，降低工作集或使用允许的更大内存预算 |
| 同 seed 输出不同 | CPU/GPU 舍入、草稿分组、适应性驻留、prompt 复用及近似默认值 | 诊断时稳定这些路径，结合 logits/任务质量，不能只比较文本 |
| 基准变快而用户延迟变差 | 排队、prompt 长度、缓存、并发或 token 统计口径不同 | 重新匹配冷/热负载，报告客户端 TTFT 和请求尾延迟 |
| CPU 测试通过但没有 GPU 后端 | 原生 kernel 和模型运行仍未验证 | 记录 `BLOCKED_REQUIRED_BACKEND`，交接明确的构建/parity/服务检查 |
| 取消后出现陈旧 token 或恢复错误会话 | 在途窗口、缓存所有权或回滚状态可能损坏 | 拒绝候选，保存失败用例，恢复基线 |
| 实验汇总拒绝数据 | ID 缺失、条件混杂、trial ID 重复或非有限数值 | 修复数据来源，不能为了提高排名而删除失败测量 |

具体命令与后端前提见[验证手册](../sub-skills/validate-engine/references/validation.md)。
