# 扩展与验证

配置无法提供目标行为，或修复已证实缺陷时使用。阅读[改动边界与验证](references/change-boundaries-and-validation.md)。

先写小型行为契约：触发条件、当前行为、目标结果、受影响所有者、允许的数值差异及最短失败观测。在用户版本定位路径，并确认所需行为尚不能通过已有配置实现。

在行为所属位置实施最小改动。遵守仓库贡献约定；本工作区提交时使用 `git commit -s`。不能假定自定义 scheduler、connector 或 backend 契约跨版本稳定。

分层验证：静态/源码契约 → 聚焦原生单测 → 设备正确性 → 服务/并发与故障路径 → 有界性能比较。优先使用改动边界已有测试，仅在能捕获缺陷时增加回归测试。记录实际运行项、依赖/硬件阻碍和准确远程后续项。

恢复：新后端、量化或传输路径不支持时，保留最近正常实现并隔离不支持的组合；不能弱化校验，也不能以改变语义的静默回退掩盖问题。交付前自查取消、生命周期、并发及配置 hash。
