# Packed-stride V diagnostic

Private candidate, UNTESTED GPU. New script diagnose-predictor-vstride-v6.py; no production/source file mutation. Actual71 predictor weights, BF16, B1/B64, fixed synthetic hidden/embed/history (or supplied captured tensors), full17,15 depths. Reference computes all trials first and clones every logit onto CPU. Then this disposable process patches only each attention instance's _split_qkv: Q unchanged, K.contiguous unchanged, V retains packed stride. Candidate reuses the same loaded weights and history; optional --compile constructs a new callable with epilogue_fusion=False after patching, relying on Dynamo method guards. Eager and compiled must be run independently and labeled.

Reports per-depth finiteness, maxabs/RMS, argmax mismatch, bitwise equality. Timing is not implemented; eligibility requires all logits finite and bitwise identical in both batches. Real SDPA backend and generated artifact lineage are explicitly UNOBSERVED/UNAVAILABLE, not assumed identical. Shape-derived expected V strides are documented separately from observations. A changed backend can change BF16 logits or eliminate any expected benefit. No service/quality claim.

Source clean/HEAD before-after, script hash, checkpoint config/per-weight/aggregate hashes, fixed input tensor hashes and seed are inherited. CPU-load smoke is separate loader/interface coverage, not the GPU layout candidate execution. No child service is started; normal process exit releases process-owned tensors. GPU execution must await parent reservation and independent review.
