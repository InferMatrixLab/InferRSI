# Campaign lessons and limits

These observations belong to [acceptance issue #112](https://github.com/InferMatrixLab/InferRSI/issues/112). They do not establish target attainment or a recommended deployment.

- **Freeze the task, not just the input strings.** A full Omni assistant may answer a sentence instead of reading it. The campaign's [readback wrapper](../plan/benchmark_readback.py) adds an explicit readback instruction while preserving original Seed-TTS references. This qualifies text-to-speech readback through the full pipeline; it does not qualify audio-input understanding or free conversation.
- **Fix measurement before optimizing.** Empty audio events must not establish TTFA ([engine PR #9278](https://github.com/vllm-project/vllm-omni/pull/9278)); one-second request buckets do not measure simultaneous concurrency ([PR #9279](https://github.com/vllm-project/vllm-omni/pull/9279)). Raw ordered request metrics allow independent aggregate checks. Throughput here counts 24 kHz PCM sample frames, not codec tokens.
- **Warm representative workloads, then observe residual compilation.** The [MRv2](mrv2-run-manifest.json), [KV](predictor-kv-run-manifest.json) and [short-KV](predictor-short-kv-run-manifest.json) screens retained inference-time JIT events. More repetitions of the first prompt alone do not cover all shapes. [Protocol v5](../plan/protocol-v5.json) therefore conditions all concurrency points and freezes whole-pair retry rules. Verbose observation required a separate configuration-forwarding fix ([PR #9281](https://github.com/vllm-project/vllm-omni/pull/9281)). Monitor coverage remains limited to supported hooks.
- **A reservation does not prove exclusive execution.** A foreign allocation was observed immediately after the [MPS screen](mrv2-mps-run-manifest.json). Its overlap with measured requests was not timestamped, so that screen cannot establish isolation or an MPS speedup. Subsequent executors continuously record owned and foreign CUDA processes and reject isolation failures.
- **Do not promote a faster-looking bundle without quality.** The [full CUDA bundle](full-cuda-run-manifest.json) retained all 256 quality outputs and produced mean WER 0.07514 versus historical baseline 0.03833. It failed that quality screen and missed both RTF targets. The existing short-KV, sampling and convolution options are credited to [upstream PR #8223](https://github.com/vllm-project/vllm-omni/pull/8223); this combined screen does not identify which mechanism caused the difference. No claim about other hardware or workloads follows.
- **Distinguish sampler seeds from full-pipeline reproducibility.** The actual deployment resolver confirms MRv2 inherits Talker seed42 from the base profile. Nevertheless, [MRv2 residual-MTP generator selection](https://github.com/amy-why-3459/vllm-omni/blob/4645c450ba4ed036433a30dfcb9782f22b0c3bfd/vllm_omni/worker_v2/model_states/omni_model_state.py#L1372) requires a model `get_mtp_seed` hook, which Qwen3-Omni does not expose. Top-level API seed applies to the comprehension stage; benchmark dataset seed alone does not seed every speech-generation component. Preserve sampling settings and repeated quality evidence; do not infer that a placement or kernel option caused every WER difference.
- **Profile time sums are not recoverable latency.** GPU kernels overlap across stages, and host synchronization often overlaps active GPU work. Use interval unions and request-level measurements rather than adding kernel durations or treating every synchronization interval as idle time. The retained [baseline profile](baseline-profile-summary.json) and [full-bundle trace manifests](full-cuda-run-manifest.json) are diagnostic observations under profiler overhead, not acceptance benchmarks.

The [source table](../plan/source-attribution.md) distinguishes existing mechanisms, deployment adaptations and new measurement fixes. Failed and inconclusive attempts remain part of the evidence; they are not removed from the search history.

## UNTESTED follow-up: device-specific MoE tuning

Status: **INCONCLUSIVE**; tuning has not been run. Installed vLLM 0.32.0 logs report missing `E=128,N=384,device_name=NVIDIA_L20X.json` (Talker) and `E=128,N=768,device_name=NVIDIA_L20X.json` (Thinker). Exact-name lookup falls back to generic parameters, not H100/H200 configurations. A missing file is not proof of a performance regression; SM90 compatibility does not establish optimal launch parameters.

The BF16, TP1 shapes are Talker `(experts=128, hidden=1024, intermediate=384, top_k=6)` and Thinker `(128, 2048, 768, 8)`. A bounded follow-up would tune representative token batches using the native utility, retain results in a task-local `VLLM_TUNED_CONFIG_FOLDER`, and validate numerical/quality behavior and the full paired service gates before promotion. Existing H100/H200 configurations are search candidates only. This does not modify the frozen campaign.

Private full-CUDA trace analysis observed `fused_moe_kernel` duration sums of 52.49 ms for Talker and 185.89 ms for Thinker. These are profiler kernel sums from an eight-request C4 diagnostic, not interval unions, recoverable latency, or measured optimization gains. See the [source verification record](../plan/source-attribution.md#l20x-moe-source-verification).

- **Separate emitted text correctness from speech quality.** The [first formal pair decomposition](formal-pair1-quality-decomposition.json) retains all 256 ordered rows: references/IDs and emitted Thinker texts match across arms, while mean WER rises from 0.037269 to 0.058449. Seven candidate rows above WER 0.5 contribute +0.023414 to the full mean difference; the remaining rows contribute −0.002234. No rows are excluded. This supports investigating the speech-output/scoring path, but identical text does not prove identical hidden states or identify a kernel, first-frame, stochastic, or scorer cause. The pair fails quality; the three-pair campaign verdict remains separate.

The [second-pair JIT diagnosis](formal-pair2-jit-diagnosis.json) records two measured Talker expert-GEMM compilation events after 16 conditioning events. Both measured events match visible conditioning compile details, but verbose logs truncate specialization metadata and cache keys; the missing specialization is unknown. Native registry warmup covers registered providers, and BF16 router warmup does not cover every expert-GEMM launch. Equal request concurrency does not guarantee identical runtime signatures. A future owner-backed expert-GEMM warmup provider plus full specialization-key digest diagnostics is **UNTESTED**. The affected whole pair remains subject to the frozen retry rule; no gate or active source change follows from this diagnosis.
