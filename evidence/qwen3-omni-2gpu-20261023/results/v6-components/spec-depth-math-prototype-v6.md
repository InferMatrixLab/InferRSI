# Window2 sampler-only mathematical prototype

Private CPU research; no GPU, model loading, engine edit or harness/seed change. Script `spec-depth-math-prototype-v6.py` uses exact Fractions and deterministic branch enumeration. Results are in `spec-depth-math-prototype-v6-results.json`.

For normalized p and strictly positive q, accepted probability for output v is q(v) min(1,p(v)/q(v)) = min(p(v),q(v)). Total rejection probability Z = sum_v (q(v)−p(v))_+ = sum_v (p(v)−q(v))_+. Rejection correction assigns Z × (p(v)−q(v))_+/Z. Hence final first token mass is p(v). After acceptance the bonus is sampled from the actual target conditional p2(.|v); after rejection, the next round resumes from the corrected v with that same conditional. The completed two-token joint is therefore p(v)p2(w|v). When Z=0, rejection has zero mass and no residual division occurs. At the one-token tail the prototype directly uses p. This proof covers arbitrary finite vocabularies and positive q; enumeration is a concrete verification of the implementation, not the proof's scope limit.

Executed checks: 90 exact joint-distribution cases over all three-token denominator4 targets (including zeros) and positive denominator5 proposals, 90 tail cases, p=q special case, four filter boundary/tie cases. No stochastic trial or significance claim.

Filter definition uses rational weights proportional to exp(logits). Retain all entries at or above kth weight, including ties; normalize, sort in a supplied tie order, keep entries whose preceding cumulative probability is below top_p, then renormalize. This matches native mathematical top-k threshold → prior-cumulative top-p definition for valid k, but does not replicate FP32 softmax/cumsum rounding or prescribe torch's tie order. Native finite-precision and full17 causal/head-position equivalence require separate real-tensor tests. It is not a production sampler implementation and supplies no RNG adapter, performance prediction or service promotion evidence.
