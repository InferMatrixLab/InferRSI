`entrypoints/openai/serving_chat.py:1666` `_build_sampling_params_list_from_request` merges standard request sampling parameters into comprehension stage; other stages clone YAML defaults. Residual predictor sampling has a distinct generator boundary. Qwen3-Omni exposes no get_mtp_seed hook (Qwen3-TTS and Moss do). MRv2 `worker_v2/model_states/omni_model_state.py:1356–1383` resolves missing model hook to None. `_prepare_mtp_sample_uniforms` at1400 draws from request generators when available, otherwise draws active and padded rows with the shared generator. Stage1 sampling_params.seed42 alone therefore does not establish a request-local residual predictor stream.

V1 `worker/gpu_model_runner.py:2060` explicitly reads sampling_params.extra_args.tts_local_seed; it does not read ordinary sampling_params.seed for this purpose. Missing tts_local_seed yields None. `_talker_mtp_forward` also forces eager treatment for explicit row generators because replaying a wrapper graph would otherwise skip Python generator handling. Thus adding local seeds can change the execution path and must not be silently mixed into performance comparisons.

`model_executor/models/common/qwen3_code_predictor.py:1268` supports per-row multinomial generators. None uses default RNG; MRv2 uniform preparation can consume draws for padded rows. Same configured seed is not proof of same per-request draws under changed batch/scheduling/graph behavior.
