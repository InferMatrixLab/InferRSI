# Frozen dependencies

The existing independently frozen task verifier and benchmark-output supplement are reused byte-for-byte from `evidence/kv-reclamation-20261030/validator/`. The actor qualifier verifies their published task-plan hashes before extracting only development traces into the worker. Grader-only traces remain with the controller and are used only after immutable submission. Runtime receipts bind current protocol/workbench/executor/qualifier hashes and the exact Git revision. Numeric timing outcomes are not a software-control CI threshold.

`tools/qualify_kv_edit_actor.py` emits `kv-scripted-actor-qualification-v1`, including the exact revision/snapshot, qualification-plan digest, canonical dependency map/digest, complete A2/A3 exposure identities, both current-revision receipt readbacks, immutable final artifact digests, hidden correctness, runtime isolation and descendant cleanup. A later launcher must validate the full field contract and current dependency closure; a generic PASS string is insufficient. Any trusted-worker refactor requires a new exact-tree host receipt. This receipt contains zero real model calls and grants no paid authority.

Each arm additionally emits `common_actor_contract_sha256`, constructed by `tools.kv_edit_inputs` from the exact arm, model/client, input ceiling, prompt, visible-suite/baseline hashes and full edit plan except its transport-specific callback digest. This binds the shared public files, limits, check identities and metric without falsely equating scripted response fixtures to live provider execution. The same helper constructs identical common public bytes and prompt for both arms; only the explicit pinned K owner differs.
