## F1 — RRSI

**Pin:** Xia et al., [2609.24972v3](https://arxiv.org/pdf/2609.24972v3), revised 2026-10-04. Full readset: §§2–3.3, Eqs.1–7, Fig.2; §§4.1–4.3, Tables1–4; Appendix A; Appendix D.1–D.3, Algorithms1–2, Eqs.8–17; Table5. Numerical evidence below uses readable table entries, not garbled PDF plot text.

- **F model/interface:** Frozen backbone; mutable harness includes prompts, control flow, tools, memory, skills and context. Eq.1 separates task score from policy-token cost. This is harness search, not weight training.
- **F proposal:** Cosine-annealed cardinality budget over independently attributable edits (Eq.4); history includes hypothesis, diff, score/cost deltas and selection outcome (Eq.10). A stalled search reserves slots for untried components (Eq.13). Bundled edits inherit the same candidate-level measurement; this is not causal component attribution.
- **F selection:** Critic screens candidate diffs before scoring. Best-ever score minus empirically calibrated noise tolerance is a non-compensatory floor (Eq.5). Above-noise gains face a relative-token-cost allowance (Eq.7); within-noise proposals use a separate score/cost/structural-novelty rule (Eq.17). Coding sets the score weight in that latter rule to zero. Recent component gains generate pruning proposals (Eq.14); deleting a component is not automatically beneficial.
- **F evidence:** Table2, agentic-workspace experiment, same base/frozen policy/evolve set/candidate budget: unregularized evolution has evolve score92.8, held-out ID88.9, three-suite OOD average40.3, 3.80M policy tokens/trial; RRSI90.5/89.2/43.6/2.42M. Base39.7 OOD and1.56M tokens/trial remains cheaper than either evolved arm. Removing proposal regularizers gives41.9 OOD; removing acceptance regularizers41.0. These are grouped ablations, not separate proof for every gate.
- **F setup:** §4.1 uses Claude Opus4.8 as frozen policy/proposer/analyst/critic; Harvey LAB120 evolve and40 ID-held-out tasks. Table5 gives20 workspace rounds and2 trials/task; its thresholds are experimental choices, not InferRSI defaults. Tables3–4 distinguish independently evolved backbones from unchanged-harness transfer.
- **F limits:** Appendix A limits claims to frozen-backbone harnesses and finite evolve sets/budgets. L0/L1/L2 are qualitative analogies; the algorithm does not optimize norm-penalized continuous objectives. Policy tokens omit other resource costs. Isolated gate effectiveness and long-horizon cross-tool-ecosystem robustness are unreported here.
- **P use:** Extend the existing search-policy evidence requirements with scoped edit attribution, noise/cost accounting and held-out transfer, without importing numerical thresholds or enabling harness edits.

## F2 — Dream-RSI

**Pin:** Zheng et al., [2609.14858v2](https://arxiv.org/pdf/2609.14858v2), revised 2026-10-06. Full readset: §§2–3, Fig.2, Eq.1; §§4.1,4.4,5, Figs.3,5–7 and Table2; Appendix B.1–B.2/Table3; Appendix D.2/Listing2 interface and prefix-observation restrictions. Related-work titles used only for next-gate leads.

- **F interface:** Fixed discovery agent, evaluator and execution interface; only exploration-policy code changes. Online action selects up to W root/leaf continuations. Offline replay reveals recorded children in parent-before-child order; a root opens its earliest unrevealed child. It cannot generate an unobserved branch outcome.
- **F objective:** Eq.1 combines normalized quality–call-count frontier hypervolume with sequential-rounds-per-call penalty over five budget preferences. Recorded worlds require positive best score and nonzero node count. This rewards discovery calls and parallelism, not measured dollars or wall-clock time.
- **F selection:** Each offline phase includes the incumbent and3 new policies in the reported settings. Best average historical replay score cannot decrease by selection, but no theorem guarantees online performance on unseen outcomes.
- **F interface detail:** Listing2 requires `OptimalPolicy.solve(self, question, budget=None)` and deterministic `plan_grid(context)` returning a non-null bounded GridPlan. Policies may inspect only revealed observations and prefix-safe historical/structural fields. Plans beyond recorded width/depth are out of replay support; current unrevealed scores are forbidden. These names are paper-specific contracts, not interfaces present in InferRSI.
- **F evidence:** §4.1/Fig.3, four KernelBench tasks, Gemini3.1-Pro, L40S (Appendix B.1), same discovery/evaluator/initialization as Recursive Fixed Exploration: VGG16/LayerNorm reach similar final performance with2.43×/1.79× fewer generations; ConvDiv/ConvMax reach2.09×/1.44× performance at comparable budgets. Appendix B.2 caps kernel runs at9 online rounds,10 workers,110 discovery calls/round,4 policy versions/offline phase. No universal total-cost speedup follows.
- **F counter-evidence:** §5/Table2 ConvDiv all-history1.90 inverse-ms at786 calls versus current-history-only1.59 at430: better quality costs more calls. Fig.6's explicit history-as-guidance treatment lowers final ConvDiv performance; it does not establish that all persistent knowledge is harmful.
- **F harness evidence/limits:** §4.4/Fig.5 improves full89-task Terminal-Bench2.1 score0.7247→0.8090 with2 runs/task and Opus4.8. §4 omits the controlled fixed-policy harness comparison because an extra search is estimated above$100,000. Discovery-call accounting does not include all policy-development/evaluation costs. Novel-branch counterfactual validity and independent isolated replay-objective-component ablations are unreported.
- **P use:** Preserve replay support and immutable evaluator boundaries in a knowledge record. Treat replay as a shortlist signal, not permission to deploy an improved controller or a substitute for fresh authorized evidence.

## F3 — AIDE²

**Pin:** Srikanth et al., [2609.26457v1](https://arxiv.org/pdf/2609.26457v1), 2026-09-22, *Recursive self-improvement of AI research agents*. Full readset: §§2.1–2.2/Eqs.1–4/Algorithm1; §§3.1–3.6/Figs.2–7; Appendix A/Tables1–2; Appendix D/Table3; §3.5 and Appendix E prompt-compression discussion.

- **F interface/objective:** Inner agent searches code under a task-visible metric and fixed budget counting tokens plus solution execution. Its selected solution receives private held-out grading; the outer agent sees aggregate grades and edits the incumbent agent. Inner selection is mutable; outer best-grade selection and task budgets are fixed in the formal loop. Private to the inner agent does not mean unseen by the adaptive outer selection process.
- **F design:** Outer AIDEhuman uses Opus4.7; inner evaluations use Gemini3Flash in the selection experiment. The main8-day100-node trajectory accepts7 rewrites, grade0.703→0.778 (§3.2). This selection trace is not itself independent generalization evidence.
- **F evolved mechanisms:** §3.5 describes UCB1 over five strategy arms with30% softmax sampling, every-five-step cross-arm forks, bounded role-specific context, and up-to-three repeated-error signatures only when bug rate≥15%. These are discovered settings, not isolated optimal values. Its median-based robust-selection penalty preserved ordering and never changed selections in replay. A reported evaluator-crash repair is a paper observation, not authorization to change InferRSI's evaluator.
- **F evidence:** Appendix A/Table1: ALE-Bench AIDE0=1536±33, AIDE85=1790±9, AIDEhuman=1511±35 private contest score;10 tasks×10 seeds, $5 primary cap per run, additional200-step/12-hour caps, Gemini3Flash. FML uses18 tasks×3 seeds,100-step primary cap and GPT5.4 instead. Do not combine these as one uniform compute denominator. ALE solutions use128-vCPU/512GB machines; FML/WeatherBench/KernelBench use A100s; MLE uses CPU containers.
- **F generalization/counter-signals:** §3.3/Fig.3: AIDE47 beats AIDE85 on MLE and WeatherBench; later accepted lineage is not monotonically better on every held-out domain. §3.4 measures reward-hacking rates55%→32% on38 held-out(kernel,training-context) pairs,3 seeds,20-step budget; Appendix A defines the proxy/downstream criterion. It does not causally identify the responsible rewrite.
- **F improver boundary:** §3.6/Fig.7 gives3 seeds/arm×50 outer steps, same AIDE47 starting incumbent: mean endpoints0.780 with AIDE47 improver versus0.782 with AIDEhuman. Authors explicitly call superiority/sample-efficiency inconclusive. Better task optimization does not establish a better improver.
- **F rejected cases:** Appendix D/Table3 contains contextual rejected proposals, including ensembles and several small grade declines described as within noise. These do not prove those algorithm families universally ineffective. Isolated causal ablations of each accepted mechanism are unreported.
- **P use:** Keep executor-quality and improver-quality claims separate. Record rejected proposals as scoped cases, not permanent global prohibitions. Require separate authorization before any harness or evaluator change.

## F4 — JitRL

**Pin:** Li et al., [2601.18510v4](https://arxiv.org/pdf/2601.18510v4), revised2026-09-27. Full readset: §§4.1–4.4/Eqs.3–12/Theorems4.1–4.3; §§5.1–5.7/Tables1–9; Limitations; Appendices C–D assumptions/proofs, F/Eqs.23–25, H–J/Tables10–14, L, N/Table19, O/Table20 and P; final Algorithm1.

- **F mechanism/interface:** Completed trajectories receive evaluator-generated step rewards, discounted into(state,action,return) memory. Retrieved neighbors estimate V/Q and advantages; adjusted candidate-action logits are z'=z+βÂ (Eq.10). Appendix F adds remembered actions to generated candidates, gives them neutral initial logits, normalizes action identity and advantage, and constrains valid actions. No weight update is involved.
- **F access boundary:** §5.1 offers index-token log probabilities or verbalized-confidence-derived logits. The latter is an approximation to an accessible action prior, not raw internal model logits. A system lacking a suitable candidate/action-scoring interface cannot obtain this behavior by merely attaching a text skill.
- **F theorem conditions:** Exact KL-regularized optimizer is conditional on the supplied advantage and reference distribution. Appendix C additionally requires state/policy regularity, unbiased bounded-variance return noise, growing covered memory, k→∞ with k/N→0, growing action counts and vanishing local policy drift. These are stronger than finite-k retrieval from an arbitrary evolving workload. Appendix D is consistency toward the induced KL-regularized policy, not unconditional globally optimal behavior.
- **F evidence:** Table8, main Gemini-2.5-flash setting, uses identical retrieval: on WebArena Admin/Reddit, logit update52.31%/57.64% versus prompt update48.35%/54.57% average success rates. Main WebArena protocol is5 repeated attempts/task; Avg averages all attempts, Final uses attempt5 (§5.2). It is not ordinary one-shot held-out evaluation.
- **F matched counter-signal:** Appendix J.1/Table13, same Llama3.1-70B backbone, training tasks excluding165 WebArena-Lite test tasks, no test adaptation: JitRL40.88% versus WebRL46.06%; reported costs$200 versus$9,900. Thus the broad stronger-performance claim does not hold in this matched offline regime. Main Table9 mixes API-billed training-free use with estimated16-H200 training costs (Appendix P), not identical hardware spending.
- **F overhead/limits:** Appendix N/Table19, Library50 episodes: retrieval rises15–22ms at0–500 entries to47ms at2000–2500 entries; this is not arbitrary-scale latency evidence. Misassigned evaluator rewards and textually aliased states are explicit risks. Appendix F's memory-action augmentation qualifies the main Limitations shorthand that candidates come only from the base model. Table11's50-episode WebArena field conflicts with §5.2's5 attempts; Appendix O's53.0 same-backbone shorthand conflicts with Table14's42.1 Qwen3-32B mean. These are unresolved source inconsistencies, not silently harmonized results.
- **P use:** Keep action reranking as a knowledge-level integration prerequisite record. Do not claim current client support, implement a logits wrapper, or promote an unconditional convergence guarantee.
